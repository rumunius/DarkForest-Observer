# 发布前成员移除补充修正

2026-11-06 用户要求比赛管理页面在“发布准备入口”之前允许移除本场成员，无论是否已接受邀请或确认本场身份。本文补充跨比赛方案 §5.3 的草稿成员管理规则；原有两份核心文档保持原文。

## 适用范围与权限

仅未发布的草稿比赛允许移除，由平台所有者、管理员或本场有效总裁判操作。玩家、普通裁判不能执行。发布准备入口后，前端隐藏移除按钮，服务端拒绝同一操作；名单已冻结或比赛恢复期间同样不能绕过原有门禁。

“本场成员”每行右侧增加一个 × 图标按钮，沿用现有图标、配色和至少 44×44px 点击区。按钮提供包含成员姓名的可读名称。确认使用站内弹窗组件，沿用现有倒角面板、遮罩与按钮样式，显示比赛、成员及释放身份或撤销邀请的后果；支持取消、Esc 和关闭后焦点归位，取消不发请求。提交沿用现有处理状态、重复提交保护、结果查询和刷新机制。

## 移除与编号回收

移除撤销本场邀请或身份关系，成员不再出现在本场列表及本人“我的比赛”中。长期账号及其其他比赛不受影响；后续可重新邀请。

玩家已分配的文明编号释放回本场分配池，接受邀请时按最小可用编号分配，范围仍为 C01—C350。新成员获得全新的玩家、飞船与攻击控制初始数据，不继承原成员昵称、母星、资源或正式名单。账号授权版本递增，旧会话失效；必要操作审计与收据保留。此处回收的是发布前的文明身份编号，不是手环码，不改变手环码永久不复用规则。

工作人员已任职的，结束其当前任职、失效旧会话和预览，将未执行管理任务转入待核对，岗位可重新任命。移除总裁判后，发布仍需重新任命一名有效总裁判；该操作不会绕过发布时至少两名已绑定玩家等既有条件。

移除在本场单事务中完成，携带当前比赛记录版本；成员接受邀请、岗位或发布状态已发生变化时要求刷新重新确认。同一请求编号重试返回原收据，不重复移除后来重新邀请的成员，也不影响已重新分配的编号。

本次修改文件的 Prettier、ESLint、`git diff --check` 通过，前端、前端测试和 Match Worker 类型检查及完整构建通过。整体 `npm run check` 在工具类型检查阶段遇到同时新增的 CSV 测试引入浏览器下载模块导致的 `document` 类型缺失（`apps/web/src/data/platform.ts`）；本次未修改该并行工作。完整 Workers 测试集未运行，仅运行上述平台集成测试。
