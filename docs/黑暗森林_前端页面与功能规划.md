# 《黑暗森林：观察者效应》前端页面与功能规划

编写日期：2026-11-03。

文档用途：确定整个网站的信息架构、页面职责、前端功能、流程状态、权限边界和响应式验收标准，供后续产品细化与开发使用。视觉语言、主题色、字体、组件外观及动效遵循[设计系统](./黑暗森林_设计系统.md)。本文规定页面内容与操作行为，不提供页面实现、视觉稿或原型。

## 1. 依据、优先级与已确认决策

### 1.1 文档关系与当前实现状态

本规划基于以下仓库文档：

- [完整策划案](./黑暗森林_完整策划案.md)：游戏规则、现场流程、信息公开范围与裁判职责。
- [技术方案](./黑暗森林_技术方案.md)：权威状态、双时基、接口边界、幂等、观战与裁判能力。

当前前端采用 Vite 与原生 TypeScript，已有首页、玩家状态、目击、裁判工作台、只读大屏五个 hash 路由及本地交互。现有底部入口中的配置和事件仍通过对话框打开。本轮只更新文档，下一轮按设计系统调整视觉，并补齐“消息”“我的”两个完整页面；本规划中的其余业务页面与正式接口仍是后续实施范围。表中路径表示产品路由，静态部署使用对应 hash 地址，例如 `#/play/messages`。

原始两份方案保持原样。本文仅对用户已经明确的前端范围与权限歧义作补充，不自行调整玩法、处罚、排名或赛事参数。后续发现新的业务矛盾时，先询问用户，再更新补充文档；不得用前端默认值悄悄决定比赛规则。

## 2. 用户角色与访问边界

| 用户身份                | 可进入的主要区域                                             | 核心边界                                           |
| ----------------------- | ------------------------------------------------------------ | -------------------------------------------------- |
| 未登录访客              | 首页、规则、登录、通用帮助                                   | 不读取本场玩家数据、比赛秘密、战报和观战态势       |
| 已登录参赛玩家          | 本人状态、准备或比赛功能、授权情报、公开事件、帮助、完赛战报 | 仅本人和服务端允许公开的数据；无全场实时击毁排行榜 |
| 永久淘汰未满180秒的玩家 | 淘汰说明、本人记录、观战等待、公开信息                       | 无正式行动，无全局观战                             |
| 永久淘汰已满180秒的玩家 | 以上内容及只读宇宙观测                                       | 保留原玩家身份；无裁判写权限，无未来随机计划       |
| 通讯／母星裁判          | 授权母星审核、通知队列、相关异常、只读态势                   | 仅职责范围能力，不因能登录后台自动获得总裁判权力   |
| 事件裁判                | 授权事件查看、通知、诊断及异常处理                           | 未来计划、补结算、纠错等分别校验权限               |
| 总裁判                  | 全场控制、终局核验、纠错、指令、限权导出等                   | 高影响操作需预览、理由与确认，并记录审计           |
| 裁判打开的只读大屏      | 当前全局赛事态势及已发生事件                                 | 校验裁判读取权限，界面和读取契约均不提供管理操作   |

裁判岗位是工作分工，实际授权以服务端能力清单为准。无需前端另造“超级玩家”身份；不能通过切换页面、修改地址或隐藏按钮代替鉴权。

同一账号淘汰、观战解锁、纠错恢复和完赛后，入口随服务端状态变化。登录失效或权限撤销时清除受限视图与内存数据；返回浏览器历史页面也必须重新确认权限。

## 3. 信息架构与页面总表

### 3.1 组织原则

玩家登录后进入“当前状态”工作台，由服务端状态指向当下最需要的流程。首航、重生、转场、核验和淘汰是连续状态，不要求玩家理解内部状态码或在多个菜单中寻找下一步。

移动端一级导航为“状态”“目击”“消息”“我的”，四项均进入有独立路由的完整页面，导航与当前任务按钮职责分开。本人信息、个人记录、规则和帮助从“我的”进入；授权公开事件与本人系统通知在“消息”阅读；情报、广播、光粒等只在对应阶段出现。低频流程放入次级页面，不把整个后台功能堆进玩家主导航。PC端保留同样的四个区域，可增加同时可见的信息量，但不改变权限或操作含义。

## 4. 首页、规则、登录与个人身份

### 4.1 首页与规则

首页只说明活动是什么、需要哪些外部工具、怎样取得参赛凭证、如何登录。不得把首页做成实时全局战局或匿名参赛名册。已有有效会话时提供“返回我的比赛”或“进入裁判后台”。

规则页按参与者任务组织：赛前准备、七色手环与目击、失败处罚、母星与重生、广播与光粒、阶段转换、终局核验、淘汰观战、排名、安全与异常。提供目录和文本查找，移动端无需整页翻到底才能找处罚或重生规则。说明内容与现行规则版本对应。

规则例子使用独立的固定配置，不读取任何玩家的当前配置；界面无需附加数据真实性免责声明。提供自行使用高德导航、前往QQ群文件查看终局圈和裁判室图片的必要说明，无内嵌图片、地图入口或校园示意图。

### 4.2 登录与会话

- 玩家输入个人独立登录口令；裁判使用独立登录入口与凭证。不规划自由注册、QQ OAuth、验证码登录或找回密码系统。凭证遗失通过指定裁判处理。
- 提交时反馈正在登录；失败说明口令无效或服务不可用，避免泄露是否存在某个玩家。登录成功后依据当前赛事与身份进入合适页面。
- 会话过期时暂停写操作，重新登录后先刷新权威状态。不得自动重新提交先前攻击、广播、出航或裁判指令。
- 凭证不出现在URL、埋点、错误报告或持久化浏览器存储中；退出后清除受限页面数据。

### 4.3 昵称与身份

首次设置昵称时显示文明编号和最终展示格式，告知确认后玩家不能自行更名。长度、重复与不合规反馈以服务端校验为准；确认前提供复核机会。已锁定时只读，更正联系裁判。所有页面用文明编号关联记录，昵称仅用于展示。

### 4.4 界面文案

所有玩家页、裁判页、大屏、按钮、提示和对话框均遵循设计系统第五节。文案使用自然、规范的汉语，直接说明当前事实、动作或真实后果；不使用防御性措辞，不添加“模拟数据”“不代表真实情况”等免责声明。

不用自创缩写、黑话或生造词，使用“禁止攻击”“离开母星”“领取手环配置”“累计识别错误次数”等清楚用语。既有玩法名称可以保留，内部枚举和代码缩写不直接成为界面标签。

禁止用“A·B”“A·B·C”“A / B”“A / B / C”及改空格、全角符号等变体罗列关键词。并列信息拆为有名称的字段，或写成自然句子。不得添加没有功能的角落英文、装饰编号、小字、副标题和口号。简洁不以删掉必要的状态、错误原因或操作后果为代价。

## 5. 玩家赛前流程

### 5.1 母星登记与审核

输入框接受六位数字字符串，保留前导零，不使用会吞掉前导零的数值转换。提供数字键盘提示但允许粘贴；不足、超长和非数字输入在本地明确提示。前端不查询高德、不判断口令能否解析，也不判断实际地点是否合规。

操作顺序为“输入口令 → 保存待审核记录 → 显示服务器保存的口令及提交版本 → 复制QQ登记消息 → 玩家在QQ发送文字与水印照片 → 等待裁判审核”。复制内容必须来自已保存版本，不能由尚未提交的输入草稿拼接。

待审核时显示最新提交时间、版本和状态；修改重交要说明新版本替代旧版本，需重新向裁判发送对应材料。通过后显示已登记并锁定；驳回后显示原因和重新提交入口；版本冲突时刷新最新记录，不覆盖裁判或玩家另一设备的新操作。

“复制成功”只表示剪贴板动作完成，不能写成“照片已提交”或“裁判已收到”。页面不设置上传照片按钮。

## 6. 比赛工作台与本人信息

状态页首区合并赛事阶段、有效比赛时间与本人状态，随后展示当前主操作和正常航行时的现役配置概览。持续限制与需要立即遵守的行为在首区说明，避免重复显示同一状态。完整指标、配置详情和个人记录放在“我的”，消息列表放在“消息”。玩家首先应能判断“我现在能否攻击、是否需要摘环、下一步是什么”。

“我的”展示文明身份、飞船状态、当前航次、母星状态或最后一命、当前两臂配置、击毁的不同文明数量、累计识别错误次数与禁止目击攻击的截止时间。配置详情可在正常出航后继续查看，不能误把历史配置标成当前配置；退役后明确标记失效。账号、规则、帮助与已有设置从该页进入各自页面，不为填充页面新增设置项目。

个人记录呈现服务端允许本人查看的结果，不曝光原始随机数、内部HMAC、他人的未授权配置或未来事件。累计识别错误次数跨航次保留，成功攻击或攻击限制结束均不清零。当前状态与结果不一致时先刷新，禁止用本地历史记录恢复资格。

重要变化如被击毁、永久淘汰、母星毁灭、阶段切换，应在前台读取到后立即改变工作台。提示应持续到玩家可理解和处理，不能只出现瞬间消息。声音和系统通知均不能成为唯一提醒方式，也不把浏览器后台推送视为已实现的送达保证。

## 7. 目击攻击

### 7.1 输入与确认

两个独立颜色集合选择区均提供七种实际色块，读取 `apps/web/src/lib/bracelet-colors.ts` 的统一配置，不把内部ID显示给玩家。每个颜色只能属于一侧；已在另一侧选中的颜色不能再次添加，移动颜色须有清晰、可撤销的交互。每侧显示所选色块及数量，支持单个移除与清空。色块的中文色名与选择状态通过无障碍名称和属性提供，界面不依赖可见色名代替颜色本身。

合法组合仅为 `2+1、2+2、3+1` 及左右互换。空臂、重复色、非法总数与非法分组不得提交，并指出具体原因。选择顺序不产生编码含义，不要求选中目标编号、昵称、衣着、外貌或坐标。

提交前在同一操作流程内展示最终两组、本人累计识别错误次数、对应处罚与本人现场观察确认，最后通过明确的“确认攻击”按钮提交。不得通过选完最后一种颜色、回车误触或长按连发自动攻击。

### 7.2 结果与处罚

| 返回结果             | 页面反馈与后续                                                                                                       |
| -------------------- | -------------------------------------------------------------------------------------------------------------------- |

| 未产生击毁           | 统一显示“本次目击未产生击毁”，展示服务端确认的累计识别错误次数及处罚，不揭示是未发行配置、准备配置、旧配置或本人配置 |
| 首次正式识别错误     | 禁止目击攻击5分钟；说明仍能被击毁，其他合法行动以当前权限为准                                                        |
| 第二次正式识别错误   | 按服务端既定结果显示永久淘汰或禁止目击攻击15分钟，不在前端抽签                                                       |

同一提交期间锁定确认动作，重试复用同一请求ID。已明确结算后不能提供“一键重复攻击旧输入”；新目击应重新观察并建立新的输入。切换到QQ或高德再回来时先同步阶段和资格，旧输入只可作为未提交草稿，不能自动发出。

## 8. 情报、正式广播与光粒

### 8.1 秘密情报

情报页仅列服务端授予本人的记录，区分成功目击获得和反向暴露获得，展示可见的文明、六位口令、来源事件、获取时间及授权状态。提供按记录查看和复制口令；不会把所有口令合并成地理视图。

玩家从外交得到的传言在QQ或线下处理，不新增网站交易市场、私聊、可验证真假的“情报鉴定”功能。若从已有授权情报带入口令到广播或光粒表单，仍必须重新确认目标和资源消耗。

### 8.2 正式广播

页面显示剩余次数、六位口令输入和本场已正式广播记录。提交前说明：成功受理消耗一次额度；会公开发报文明及口令；真实母星主人将获得发报者母星情报；可能触发歌者清理。

不在提交前提示“真实母星”“空地”“属于某文明”。重复公开口令不再消耗额度，最终以服务端校验为准。成功后展示权威剩余次数和公开事件；失败或结果未知时不自行扣额度。

### 8.3 光粒

仅向有资格的本人显示可用状态；未获光粒者不看到其他文明中奖情况。返航时即使获得光粒也不能发射，正常出航且第一阶段才按权限开放。

发射前确认六位口令、一次性消耗以及不保证摧毁母星。无需先广播，不鉴定目标。成功后显示服务端结果，公共事件隐去发射者；私人本人记录和授权裁判／观战记录按各自权限显示。

65:00后广播、光粒、母星业务与重生入口关闭；未使用光粒只保留为历史事实。不能因旧表单尚在屏幕上而继续提交。

## 9. 普通重生

只有第一阶段被合法目击击毁且母星仍在的玩家进入此流程。页面顶部持续展示唯一的重生截止和当前剩余有效时间，截止为击毁后15分钟与65:00二者中更早者；不能每进入下一步重新开始计时。

1. **被击毁提示：** 明确尚可重生、立即在安全位置摘掉全部比赛手环，停止目击攻防，步行返航。
2. **返航与QQ材料：** 获取本次重生模板，玩家自行拍水印照片并通过QQ私聊发送；点击已完成返航和发送声明后进入准备状态。普通重生不逐次等待裁判批准。
3. **离开母星并领取配置：** 提醒保持摘环并离开母星至少50米，由玩家声明；满足时限后领取新配置。网站不测距、不要求地理打卡。
4. **换码佩戴：** 显示本人新准备码，在安全位置戴好全部要求手环，其余收起。待激活码不能当作已出航。
5. **完成出航：** 服务端成功后显示恢复攻防资格；若仍在个人禁止目击攻击期间，只恢复可被攻击等相应能力。

母星中途毁灭、65:00到达或截止前未成功出航时，立即转淘汰状态。网络未知不能显示“出航成功”。码源耗尽时显示赛事异常及联系裁判，不改成个人重生次数耗尽，不复用旧码。

### 10.2 转场页与终局核验

转场页用清晰文字说明“在比赛QQ群加入同一场实时位置共享”“正常步行进入群文件标明的终局圈”“98:00为资格截止”。提供群名称、相关文件名称等经主办方确认的文字信息；不放缩略图、示意图、路径线、校园坐标或到达倒计时预测。

不把“打开QQ”“复制说明”当成已共享，不提供“我已入圈”来替代人工裁决。98:00后显示比赛有效时钟冻结和核验中，不把真实等待时长算入最后22分钟。玩家在高德或QQ停留后返回网页，先刷新当前状态，再显示相应动作。

### 10.3 淘汰与观战解锁

立即展示淘汰原因和生效时刻、全部摘环、停止侦察和情报传递、按群文件参考返回裁判室的提示。180秒按服务端有效淘汰UTC起算，全场暂停不冻结；98分钟批次可能在实际提交时已经满足等待期限，以服务端返回为准。

倒计时到零先请求资格，再开放观战。纠错恢复参赛资格时撤销观战路由、清除已加载受限数据并回到对应玩家状态；不能声称已展示过的情报能够被撤回，裁判复核需要考虑既有信息暴露。

## 11. 只读观战与独立大屏

宇宙观测以文明列表、状态统计和事件时间线表达，不设计“宇宙地图”、节点位置图、校园关系图或其他暗示实际空间布局的界面。可查看以下已授权事实：

- 文明编号、昵称、存亡、当前航次与返航期限。
- 母星真实六位口令与存亡、正常出航者的当前两臂配置。
- 已发生攻击、处罚、广播、清理、重生和阶段事件。
- 当前光粒、广播资源及已产生战绩。

支持按文明、事件类别和时间筛选；查看详情时保留列表位置。观察者看到的全局战绩属于受限观战信息，不在玩家公共事件页变成实时排行榜。

O04大屏由有权限裁判打开，使用明确标识的只读显示模式。桌面主工作屏继续处理裁判事务；展示屏仅查询规定的观战数据，不复制整个后台页面，不显示待发送私聊、随机计划、原始抽签值、凭证、审计秘密或指令入口。无需全屏权限也能工作；全屏是可选显示方式。

大屏与移动观战来自同一态势定义；大屏可同时展示更多文明及近期事件，手机以概览、列表和单文明详情逐层进入。大屏登录失效或读取权限失效时遮蔽敏感数据并提示重新授权。大屏只读是该展示功能的边界，不意味着裁判账号本身被降权。

## 12. 裁判后台功能

### 12.1 工作台与名册

J01聚合阶段、有效时间、暂停原因、T0／T1状态、存活及返航人数、母星审核数、就绪数、未发送通知、码源余量与调度告警。优先链接到需要处理的具体记录，不仅展示统计数字。

J02按文明编号查找玩家，查看昵称、登记／缺席、当前状态与权限相关记录。昵称更正、凭证补发和身份恢复需相应权限与审计，不显示已有登录口令明文。固定账号批量创建、凭证交付等服务端能力在原方案中有要求，但完整GUI接口尚未定义；规划为赛前受控操作，不把凭证下载做成默认公开功能。

不增加用户自助退赛按钮；正式退赛或赛前缺席由裁判按既有规则登记。名单锁定、已发行码退役及排名资格由服务端处理。

### 12.2 母星审核与首航管理

母星审核列表显示文明、最新六位口令、版本和等待状态。详情引导裁判在QQ核对照片与同版本消息，并在高德人工核验；网站内无图片面板或地图。提交审核携带预期版本及口令，过期则刷新并重新核对，不能把旧QQ照片批准到新记录。

通过或驳回后显示服务端结果；重复口令、实际地点不合规、材料不一致分别提供可理解的处理说明。驳回需理由。实际地点是否重复由裁判在外部工具核验，不用六位字符串不同推断地点不同。

首航管理按名单展示母星审核、材料与离开母星声明、领取配置前就绪、已领取配置、穿戴就绪，说明尚未完成准备的成员及原因。总裁判锁定T0前全部正式成员须满足资格条件；锁定T1前全部须已穿戴就绪且准备配置合法。前端显示检查结果，实际资格由服务端事务校验。

### 12.3 比赛控制

显示赛事有效时钟与服务器当前时间，区分全场暂停、仅禁止目击攻击、个人攻击限制及终局核验暂停。暂停或恢复前说明作用范围并要求原因，成功后显示权威回执；网络未知时先核实，不能用按钮已点击表示暂停已生效。

98:00核验暂停只能走完成核验流程。常规界面不提供随意拖动时间轴、跳阶段或强制开战来绕过规则；必要异常交由有权限的控制台与纠错流程处理。

### 12.4 QQ通知队列

按群公告／私聊、优先级、等待时间、事件类型和状态筛选，优先处理失联及永久淘汰通知。详情显示准确收件文明、事件编号、生效时刻与应发文本，支持复制和独立标记已发送。

`pending → copied → sent`分别表示待处理、已复制、裁判确认发出；发送异常可标记并重试。同一事件与收件者不得出现重复任务。网站不自动操作QQ，不将复制视为送达，也不将裁判标记已发送视为玩家已阅读。

多人同时处理时应显示最新发送状态与操作者，冲突后刷新，避免重复发送。筛选和列表刷新不能把用户正准备发送的收件人悄悄替换。

### 12.5 98分钟资格核验与终局执裁

1. 90分钟起提供存活文明名单，裁判自行在QQ和现场核实；列表不接收位置数据或显示自动定位结论。
2. 98分钟后显示核验暂停和截止说明。裁判为拟淘汰者选择“截止未共享”或“截止仍在圈外”；未选择不等同已核验，工作流中明确区分待核对与已核对。
3. 总裁判提交前逐项复核名单及原因，并确认未列入名单者的资格已核对。页面展示拟淘汰数量、预计剩余人数和提交后可能开战／提前完赛的结果。
4. 空淘汰名单也可完成核验，必须是明确确认后的操作。统一提交由服务端一次结算；不得为模拟批量效果逐人调用淘汰接口。
5. 成功后显示本批次结果；两人及以上进入完整22分钟最后狩猎，一人或无人直接完赛。若名单或状态发生变化，重新拉取并复核，不能自动丢弃某行后继续执行。
6. 开战后对离圈、共享中断或定位违规逐人裁决，使用相应原因并展示实际生效时刻，不混入98分钟并列批次。

待核对标记属于裁判工作流辅助，不代表网站验证过位置；其共享草稿能力若需要跨裁判协作，必须另行定义接口，不能在前端伪装成持久化裁决。

### 12.6 单文明详情、争议与换码

单文明详情串联状态、航次、母星、资源、攻击、识别错误、淘汰、通知和审计，按权限隐藏不必要秘密。攻击争议区区分玩家可见中性结果与裁判可见的详细分类、可信竞速证据和处罚记录。桌面并行对照名册和详情，手机进入可返回的完整详情页，返回保留名册筛选与阅读位置。

纠错必须先展示目标事件、现状态、拟变更及连锁影响，包括码本、重生时限、观战权限、情报暴露、通知与战绩；执行需要理由。不得把“撤销”做成无审计的删除，或为第二次识别错误提供重新抽签按钮。

设备异常换码遵守原方案的暂停、旧码退役、新码发行及资格处理。记录旧码已失效并永久占用容量，不能以“重新显示配置”名义额外发行。具体细节由服务端受控操作返回，前端不自行拼接修改多个状态。

### 12.7 事件、调度与码本

已发生事件列表与未来计划分区授权；未来歌者、技术爆炸及随机相关数据只向具备职责的裁判展示，不能复用到大屏。健康页面显示最近调度、积压、失败和最后同步时间。重排、补结算有独立操作、原因与回执，不因刷新页面自动执行。

码本页显示已发行、剩余、预留、现役及退役统计，并明确所有已发行码均占本场容量。余量20／10／0按原技术方案告警；第351枚需求失败时提示总裁判暂停处置。普通后台首页无需暴露350枚完整配置。

### 12.8 指令控制台与审计

控制台提供服务端返回的命令帮助、参数说明、目标选择和自动补全。只读查询可以直接执行；带副作用命令必须区分编辑、预览和执行，中高影响操作确认理由与作用范围。预览过期或目标状态变化时重新预览，不把旧预览当成执行保证。

界面支持查询诊断、比赛控制、玩家与资源、事件管理、消息情报、参数效果、调度组合及审计修复的已注册能力；具体命令语法以服务端帮助为准，不能将原方案示例误当成已经实现的命令列表。不提供任意SQL、JavaScript或Shell执行器。

执行历史显示请求ID、操作者、来源、原因、目标、执行结果与关联审计。纠错、高维干涉和补结算分别标明来源，不冒充正常玩家行为。审计页面可按文明、事件、操作者、时间和类别检索；敏感字段按权限裁剪。

### 12.9 战报核对与导出

后台展示服务器正式结算结果、结束原因、版本与纠错关联。战报导出与受限审计导出分开选择，明确数据范围；普通战报不能夹带真实母星全量清单、当前配置、原始抽签、登录凭证、QQ材料或未来计划。

导出是只读功能，失败可重试，不改变比赛结算。大规模历史恢复和基础设施PITR不规划为常规一键按钮，按技术方案的应急流程由总裁判审查后执行。

## 13. 赛后战报

仅比赛正式结束后向本场已登录玩家及裁判提供；未结束时说明比赛尚未完赛，不显示暂定全场排名。淘汰玩家即使尚未满180秒，也可在完赛后读取这份受限战报，但不因此提前获得全量观战权限。

战报包含比赛结束原因及有效时刻、幸存者和淘汰者分组、服务器给出的正式名次、击毁的不同文明数量、淘汰时间和并列组、个人总结与经过公开范围筛选的赛事时间线。支持定位本人、文明查询和阅读排名说明。

前端不自行用时间或积分重排：幸存者优先，同分并列并跳号；淘汰组服从服务器生效时刻、顺序及同时淘汰分组。分别处理正常120分钟结束、仅余一人和全员淘汰；全员淘汰不能把第一名标成存活冠军。

不提供匿名分享令牌或免登录分享页。分享普通页面地址后，访问者仍须有本场身份。战报纠错后显示版本与更新说明，不能继续展示旧名次为最终结果。

## 14. 跨页面状态、时钟与弱网行为

### 14.1 双时基

| 时间项                                             | 权威依据            | 全场暂停时                 |
| -------------------------------------------------- | ------------------- | -------------------------- |
| 阶段、重生期限、歌者与技术爆炸                     | 有效比赛时钟        | 冻结                       |
| T0／T1开赛前安排                                   | 服务器确定的UTC时间 | 读取服务端安排，不自行变更 |
| 识别错误导致的攻击限制、180秒观战解锁、UTC临时静默 | 服务器UTC截止       | 继续经过                   |

前端可根据最近快照平滑显示时间，但到期后的资格、攻击结算、出航、淘汰和阶段切换必须重新同步。熄屏、切换应用、网络断开与浏览器定时器停顿均不改变服务器赛事运行。

### 14.2 通用请求状态

每个读写区分初次加载、可用、提交中、成功、明确拒绝、结果未知、断网、会话过期和权限变化。空列表必须区分“确实无记录”“筛选无匹配”和“未能加载”，不能用空白界面掩盖错误。

写请求提交后保留稳定请求ID及待核实状态；对不确定结果优先查原结果，必要重试也复用原ID。请求结果查询的具体契约尚需补齐，不得将前端超时当成服务端失败。刷新或重登后也不能自动生成新ID重发。

### 14.3 同步与应用切换

采用可调整的状态刷新机制；原技术方案以轮询为基础，具体间隔由现场网络与接口负载测试决定。只刷新当前权限和页面必要数据，避免每个组件各自重复轮询。恢复前台、写操作完成和收到权限变化时立即重新同步。

用服务端状态版本或等价机制拒绝过时响应，防止较慢旧请求覆盖新状态。多标签页、跨设备和多人裁判冲突都以服务端为准。断网时显示最近同步时间及状态可能过期，关闭需要权威确认的提交；网络恢复后核对待处理请求与当前状态。

不规划离线战斗、离线排队攻击、离线裁判提交或自动补发批量操作。已复制文本与未提交草稿不得当成权威事实。个人秘密默认仅保留在当前会话内存；持久化恢复所必需的最小请求标识也须与场次和账号绑定。

### 14.4 消息与外部应用

“消息”页汇总当前身份可读取的公开赛事事件与本人系统通知，并清楚区分类别、时间和可进入的相关记录。沿用已有事件和本人记录，不扩大信息公开范围，也不要求新增独立消息服务。旧公开事件地址可作为该页的筛选入口或兼容跳转，不维护两份相同列表。站内消息不聚合QQ聊天、照片或位置共享，不提供站内聊天、QQ收件或代发能力。

复制失败时展示可手动选取的完整文本。无论复制还是手动选择，都给出“请自行前往QQ发送”的后续说明。不能保证或假装检测高德、QQ已打开、照片已发送或位置已共享。

手机从QQ、高德或锁屏返回时保留合理的阅读位置和未提交输入，但危险操作需更新资格后重新确认。页面不要求长期常亮，也不以Web Push、后台轮询、振动或音效作为唯一通知通道。

### 15.2 可用性约束

- 以320、360、390、430 CSS像素宽的竖屏浏览器，以及768、1024、1366、1920宽度的平板／PC环境作为建议验收样本；这些是测试尺寸，不锁定CSS断点。
- 页面整体不出现非必要横向滚动。长表格、原始审计与命令文本可在独立区域滚动，但主要身份、状态与确认动作必须容易找到。
- 主要触控目标建议至少44×44 CSS像素，危险动作与相邻普通动作保持可区分的操作区域；不依赖悬停或双击完成关键功能。
- 兼容安全区域、浏览器地址栏伸缩、软键盘弹起、横竖屏切换和窄桌面窗口。操作区不能遮挡字段错误、最后一条记录或确认信息。
- 文本放大到200%仍可完成主要流程；按钮名称不只用图标，状态不只用颜色表达；手环以实际色块为主，中文色名通过无障碍名称提供，选择状态同时使用描边、勾选和可读取属性表达。
- 手机底部四个入口均使用独立页面与当前页标识，保留底部安全区域，不遮挡最后一条内容。消息、本人信息和配置详情不以对话框代替完整页面。
- 支持键盘逐项访问、明确焦点、表单标签和错误关联。打开确认流程后焦点可控，关闭后返回触发位置；屏幕阅读器能够理解阶段与结果，倒计时不逐秒打断播报。
- 敏感数据不通过鼠标悬停才可阅读，也不在后台页面默认全部铺开；大屏显示与裁判管理内容分离。

目标浏览器覆盖iOS Safari、Android Chrome及常见Android系统浏览器、手机QQ内置浏览器，以及桌面Chrome、Edge、Firefox、Safari的实际可用版本。具体正式支持版本应在开发验收时登记实测结果，不能仅凭桌面模拟尺寸宣称移动兼容。

以上规定交互与可访问性，具体视觉尺度、色值、字体、组件和留白遵循设计系统。裁判桌面保留并行核对能力，手机核心功能不因视觉精简而删减。

## 16. 前端模块与接口对照

### 16.1 建议模块职责

前端可按账号会话、公开规则、玩家状态、本人信息、手环配置、目击、母星与出航流程、情报与宇宙行动、赛事消息、QQ消息模板、观战、裁判工作台、管理指令和战报划分模块。共用身份格式化、六位口令输入、双时基显示、请求状态与权限检查，但不混用公开、玩家私密、观战和裁判响应。

`apps/web`承担浏览器界面，`packages/contracts`仅放可公开的契约；权威规则与秘密保留在服务端。当前前端沿用 Vite 与原生 TypeScript，本轮不引入新的框架、状态管理或UI库。

## 18. 功能与兼容验收清单

### 18.1 范围与权限

- [ ] 所有页面、静态资源引用、导出与大屏均无地图、导览图和校园布局绑定；没有定位请求、路线规划、照片上传或QQ位置采集。
- [ ] 首页与规则免登录；个人信息、战报、观战及后台直接访问均执行相应身份检查。
- [ ] 正常出航可查看本人现役配置，普通玩家不能获取其他文明配置；服务器响应而非CSS隐藏承担隔离。
- [ ] 未满180秒无法获得观战数据；解锁与纠错撤销都由服务器判断；裁判可独立登录只读大屏。
- [ ] 光粒发射者、未来计划、随机审计、登录信息和私聊资料不会出现在普通玩家公开信息或大屏。

### 18.2 玩家核心流程

- [ ] `001234`前导零保留；母星重交后版本更新，QQ模板取最新已保存版本，旧版审核被拒绝。
- [ ] T0前无配置；T0领取配置重试不新增发行；T1前无攻防；全员就绪由服务器校验。
- [ ] 仅合法七色分组可提交；左右互换和同臂顺序不改变语义；色块来自单一配置，中文色名和选择状态可由辅助技术识别，不显示内部颜色缩写。
- [ ] 三次识别错误处罚、无惩罚拒绝、首次击毁计数和直接淘汰均展示权威结果，不泄露旧配置分类。
- [ ] 重生共用一个截止，跨步骤、切应用和刷新不重置；正常重生不要求逐次审核；出航成功以回执为准。
- [ ] 母星毁灭、65分钟、90分钟、98分钟与完赛会撤销旧页面中的不合法操作。
- [ ] 广播重复不重复扣次数，光粒失败或超时不自行扣库存；结果未知使用同一请求核实。
- [ ] 转场无“网页确认入圈”，核验期间冻结有效时钟，恢复后最后狩猎时间正确。

### 18.3 裁判流程与一致性

- [ ] 审核、通知和核验多人协作时检测过期数据；旧响应不覆盖新操作。
- [ ] 复制与已发送状态独立；通知发送延迟不改变攻击生效与重生截止。
- [ ] 98分钟空名单、多名淘汰、仅余一人、全员淘汰均能完整提交；同批次不会拆成逐人结算。
- [ ] 普通恢复不能结束核验暂停；终局开战后淘汰记录与截止批次区分。
- [ ] 纠错、换码、补结算和指令执行显示影响、理由、请求ID与审计，不重抽处罚、不复用旧码。
- [ ] 码源20／10／0告警和无法发行新码均有明确处理入口；异常不误标成个人次数用尽。
- [ ] 战报名次完全采用权威结果；同分跳号与全员淘汰无冠军正确；导出范围符合权限。

### 18.4 双端与异常场景

- [ ] 状态、目击、消息、我的均有独立路由和完整页面，直接访问、刷新、浏览器前进后退和当前页标识正确，没有一级入口以弹窗或动作按钮代替页面。
