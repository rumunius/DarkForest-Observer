# 工程骨架与开发环境

编写日期：2026-11-02。本文是工程补充说明；原始完整策划案与技术方案保持原样。

## 1. 本次范围与技术选择

沿用技术方案的 Cloudflare Pages + Pages Functions + 独立 SQLite-backed Durable Object Worker。
不另建 D1、KV、R2 或外部数据库，不引入另一份权威比赛状态。

文档没有指定前端框架。本次先采用 Vite + 原生 TypeScript 的空入口，避免提前锁定 React/Vue、组件库或路由方案。
尚未安装 Hono、状态管理、运行时校验库、UI 库等业务依赖；后续实施时再按实际需求选择。

使用 npm workspaces 管理三个工作区；共享一份 lockfile，开发工具版本精确锁定。

已配置 TypeScript 严格模式、ESLint、Prettier、Vitest 入口、编辑器格式规范与只检查不部署的 GitHub Actions。
Vitest 只配置了未来的单元测试目录；没有编写测试用例，CI 当前只运行 `npm run check`。
Workers 集成测试和浏览器端到端测试各有预留目录，尚未安装对应测试运行器。

```text

├─ apps/
│  ├─ web/
│  │  ├─ src/

│  │  ├─ functions/
│  │  │  ├─ _middleware.ts        仅透传，不鉴权、不处理业务
│  │  │  └─ api/                  预留同源 API，不含端点
│  │  ├─ public/
│  │  │  ├─ maps/                 预留自行托管的终局地图

│  │  │  ├─ _headers              静态资源基础响应头
│  │  │  └─ _routes.json          Functions 仅覆盖 /api/*
│  │  ├─ vite.config.ts
│  │  └─ wrangler.jsonc
│  └─ match-worker/
│     ├─ src/

│     │  ├─ services/             预留统一权威操作与事务编排
│     │  ├─ storage/              预留 SQLite schema、仓储、版本升级
│     │  ├─ scheduler/            预留双时基事件队列与 Alarm 调度
│     │  └─ rpc/                  预留内部 RPC 边界
│     └─ wrangler.jsonc
```

空目录通过 `.gitkeep` 纳入版本控制。前端、Functions、Worker 分别进行类型检查；浏览器与公共契约禁止导入 Worker 或 Functions 模块。

后续所有权威比赛写入应进入同一场次的 DO；Pages Functions 负责入口，不直接写独立比赛数据库。
`storage/` 目前没有 SQL 文件。Wrangler 中的 `new_sqlite_classes` 是平台存储迁移声明，不是业务数据库建表。

## 3. 本地开发与验证

```powershell
cd E:\forest
npm ci
npm run dev
```

`npm run dev` 先构建空静态外壳，再并行启动：

| 进程            | 地址                    | 内容                                             |
| --------------- | ----------------------- | ------------------------------------------------ |
| Vite            | `http://127.0.0.1:5173` | 前端开发入口，`/api/*` 代理到 Pages              |
| Wrangler Pages  | `http://127.0.0.1:8788` | 静态构建、Functions 与内部 DO 绑定               |
| Wrangler Worker | `127.0.0.1:8787`        | 内部 Worker，本地开发端口，不实现 fetch/RPC 业务 |

三个进程均只监听回环地址，不创建远程资源。首次启动时绑定可能短暂显示 `[not connected]`，待 Worker 就绪后应变为 `[connected]`。

本地存储共用仓库根目录 `.wrangler/state/`，与云端 preview 隔离；生成的环境类型在各工作区 `.wrangler/types/`。
这些目录均被忽略，重装依赖后执行 `npm run cf:types` 或 `npm run check` 即可重新生成类型。
修改前端时访问 Vite 入口获得热更新；在 8788 检查最新静态产物前，需要重新运行 `npm run build:web`。

```powershell
npm run check
```

此命令依次检查格式、ESLint、三工作区及配置文件类型、前端构建与 Worker 的 preview dry-run。
`--dry-run` 不上传、不部署、不建立云端 DO，也不执行数据库初始化。

```powershell
npm run test
```

当前没有业务测试，Vitest 会报告没有测试文件并返回非零状态；没有使用 `passWithNoTests` 把空测试伪装成成功。
后续有测试用例后再将测试命令加入 CI。

`_headers` 只为静态资源配置基础 CSP、内容类型和权限响应头；未来 Functions 的私有禁缓存、Cookie、Origin/CSRF、鉴权和权限过滤仍需业务开发与验收。
需要验证 Secure Cookie 等 HTTPS 行为时，使用云端 HTTPS preview 或单独配置本地 HTTPS；当前空骨架没有登录会话。

`MATCH_DO` 绑定由 Wrangler 配置管理，后续不要同时在控制台维护相互冲突的绑定值。
当前没有写入 `account_id`，登录后根据实际可访问账户确定；如有多个账户，应先确认目标账户。

## 5. 环境变量与密钥

- 普通配置放在各自 `wrangler.jsonc` 的 `vars`。
- `.dev.vars.example` 仅说明未来服务端变量，没有可用密码或占位凭证。
- 本地真实密钥应写入对应工作区 `.dev.vars`，云端通过 Cloudflare Secrets 注入。
- HMAC、加密、会话和裁判相关密钥尚未生成、尚未配置，也没有被当前空代码消费。
- 公共契约不得保存密钥、内部审计数据或未来随机事件；任何 `VITE_*` 变量都应视为浏览器公开数据。
- `.env*`、`.dev.vars*`、`.wrangler/`、私钥、日志、研究缓存、备份和赛事导出均已加入 `.gitignore`，示例文件可提交。
- npm 12 的依赖安装脚本只明确允许当前锁定版本的 `esbuild` 和 `workerd`；升级这些包时须重新检查版本对应的安装许可。

不要提交 Cloudflare token、OAuth 凭证、业务密钥或真实玩家数据。
