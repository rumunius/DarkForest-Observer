# 《黑暗森林：观察者效应》设计系统

编写日期：2026-11-03。

本文定义网站的视觉语言、界面文案、响应式布局与组件使用方法。视觉方向参考用户提供的黑底线框界面，保留其安静、克制和精确的气质，不照搬原图排布。设计师与前端工程师扩展页面时，以本文和[前端页面与功能规划](./黑暗森林_前端页面与功能规划.md)为共同依据。游戏规则与信息公开范围由完整策划案、技术方案和前端页面规划确定。

本文是下一轮界面改版的目标规范。本次更新限于文档，现有前端尚未按本文改版。两份原始策划文档保持只读。

## 1. 设计立场

### 1.1 空旷、安静、精确

界面以黑色和白色为主，采用严格扁平化的几何构成。深空感来自大面积纯色留白、稳定的边界和清楚的比例，不依靠插画、星空纹理、发光效果或动效。

页面保持信息克制。首屏只放页面身份、当前状态和当前任务需要的操作。删除不能帮助识别页面、理解状态或完成任务的副标题、角落文字、口号、编号和装饰说明。标题直接使用页面名称；首页也不例外。

使用细线、直角分隔和少量切角表达观测设备的几何感。每个几何元素承担分组、定位、选择或操作含义；不添加无功能的准星、坐标、仪表或控制点。参考图的手部造型、背景光照、星点和底部装饰符号不作为实现要求。

### 1.2 信息先后顺序

玩家页顶部以一个简洁状态区合并当前阶段、有效比赛时间和本人状态，随后展示当前可用操作与手环配置。首屏只保留必要指标；完整个人记录和事件列表分别进入“我的”与“消息”。持续有效的限制放在状态区，避免相同状态在多处重复。

裁判首先看见比赛时间、阶段及待处理事项，随后对照文明名册与详情。影响全场的操作经过填写原因、预览和确认。

观战大屏采用统计、文明列表与事件时间线，不表达真实空间位置。

## 2. 色彩与字体

### 2.1 网站主题色

主题变量统一维护在 `apps/web/src/styles.css` 的 `tokens` 层。下表为改版目标色值，代码尚未同步。后续实现时统一替换主题变量及相关样式，禁止在页面组件中另写一套色值。

| 变量        | 色值      | 用途                           |
| ----------- | --------- | ------------------------------ |
| `--bg`      | `#08090B` | 全站纯色底                     |
| `--surface` | `#0E1013` | 输入区及少量需要分组的工作区域 |
| `--text`    | `#F0F1F2` | 标题与正文                     |
| `--muted`   | `#A2A6AA` | 次要但必要的信息               |
| `--subtle`  | `#858B90` | 禁用态和低优先级字段           |
| `--line`    | `#41474C` | 边界和分隔                     |
| `--blue`    | `#7899B1` | 焦点、链接和少量选中标记       |
| `--yellow`  | `#C9B85F` | 当前页签和重要状态标记         |
| `--red`     | `#B96565` | 错误和危险状态                 |

背景不使用渐变、阴影、光晕、纹理或毛玻璃，不叠加半透明色面制造空间层次。全站主操作使用描边或纯文字，不铺大面积强调色。蓝、黄、红只作为小面积状态提示，例如一条短线、一个图标或一个必要状态值；同一视图内通常只突出一种强调色。正常状态默认使用正文色，不额外引入绿色。手环色是唯一允许鲜明色块的业务元素。

页面用纯色和细线区分内容区域，不通过一层套一层的卡片制造层级。普通内容尽量直接放在页面网格中；只有需要清楚界定操作边界的面板才使用细边框。按钮采用直角或极小圆角，不使用胶囊形控件。`--line` 用于非交互分隔；输入框和描边按钮使用 `--subtle` 保证边界可辨，正文对比度至少达到 4.5:1，有辨识作用的控件边界与背景对比度至少达到 3:1。

### 2.2 七色手环的统一配置

唯一配置入口为 `apps/web/src/lib/bracelet-colors.ts`。修改每种颜色的 `hex` 即可更新选择器、本人配置、裁判详情和大屏。`id` 是稳定的业务标识，`name` 用于无障碍名称。

| 标识 | 名称   | 初始色值  |
| ---- | ------ | --------- |
| `BK` | 黑色   | `#16191E` |
| `WH` | 白色   | `#F1F0E8` |
| `GY` | 灰色   | `#8B949E` |
| `YL` | 黄色   | `#F3D45E` |
| `OR` | 桔色   | `#F38A43` |
| `SB` | 天蓝色 | `#76C9ED` |
| `PU` | 紫色   | `#AE8CDA` |

色块是手环颜色的主要表达，界面不重复铺设可见颜色名称。色块直接读取配置中的色值，并在无障碍名称中提供对应中文颜色名。选中状态通过白色描边、几何勾选标记与 `aria-pressed` 共同表达；已在另一侧选中的颜色在当前侧禁用。黑色色块保留白色描边，避免融入背景。

手环色与网站状态色分别维护。网站主题变化时，手环仍使用这里的固定配置。

### 2.3 字体

中文与正文采用 Noto Sans SC Variable。编号、时间、数量及六位口令采用 IBM Plex Mono，使用等宽数字。字体通过 npm 安装并由 Vite 本地打包，遵循已有同源 CSP。

| 层级     | 桌面建议 | 手机建议 | 字重 |
| -------- | -------- | -------- | ---- |
| 页面标题 | 28–32px  | 26–28px  | 500  |
| 状态标题 | 22–26px  | 21–24px  | 500  |
| 章节标题 | 16–18px  | 16–18px  | 500  |
| 普通正文 | 15–16px  | 15–16px  | 400  |
| 次要信息 | 13–14px  | 13–14px  | 400  |
| 玩家计时 | 48–64px  | 42–52px  | 400  |
| 大屏计时 | 56–88px  | 48–64px  | 400  |

不设置无用途的装饰文字层级。字段名和次要信息仍应清楚易读，不为追求空灵感而压低对比度。长篇规则正文使用 16px，行高约 1.8。

## 3. 构图与响应式

### 3.1 基础尺寸

间距以 4px 为基本单位，常用 8、12、16、20、24、32、40px。内容区左右保留稳定外边距，允许相邻区域之间有充足空隙。面板仅在需要时使用边界，内边距在桌面为 24px，手机为 16–20px；极窄屏为 12–16px。默认直角；明确需要柔化分组时圆角最多 2px。

按钮最小高度为 48px，图标按钮为 44px。色块选择器的点击区域至少 44px 高，手机采用四列，防止七列布局压缩触控宽度。

页面整体避免横向滚动。原始文本或未来的宽审计表可以在自己的容器中滚动。

分隔线以 1px 为主，同一层级保持统一；键盘焦点可使用 2px。切角可选，采用统一的 6px 斜切，最多出现在同一容器的一对对角，不给每个字段和按钮都加外框。手机主要内容区块间留出 24–32px，桌面留出 32–48px。空白承担分组作用，页面不为填满视口而添加内容。

### 3.2 布局断点

| 宽度       | 布局方式                                       |
| ---------- | ---------------------------------------------- |
| 小于 360px | 收紧外边距，大屏文明列表改为单列               |
| 360–767px  | 手机单列，底部四页导航，裁判详情使用独立页面   |
| 768–900px  | 窄侧栏，内容按宽度降为单列或双列               |
| 901–1199px | 中等侧栏，裁判名册独占主列，详情作为内容页查看 |
| 1200px 起  | 完整侧栏，裁判名册与详情同时显示               |
| 1600px 起  | 扩大内容留白，大屏文明列表支持四列             |

手机底部导航的四个入口为“状态”“目击”“消息”“我的”，每项都导航到对应的完整页面。四页都使用一致的顶部标题区、滚动内容区和当前页签状态。点击“消息”进入消息列表；点击“我的”进入身份、个人记录和已有设置入口，不为填充页面新增设置。它们不能用弹窗代替页面，也不能只作为执行单个按钮的入口。表单确认、简短核对和轻量选择可以使用对话框，但用户需浏览、筛选或持续返回的内容必须有独立页面。

| 底部入口 | 页面路径         | 主要职责                                       |
| -------- | ---------------- | ---------------------------------------------- |
| 状态     | `/play`          | 当前阶段、时钟、本人状态、主操作和现役配置概览 |
| 目击     | `/play/sighting` | 颜色输入、核对、提交和结果                     |
| 消息     | `/play/messages` | 公开赛事事件与本人有权查看的系统通知           |
| 我的     | `/play/self`     | 身份、配置详情、个人指标、记录及设置入口       |

静态部署使用对应的 hash 地址，例如 `#/play/messages`。页签使用链接和 `aria-current="page"`，当前项以白色图标、文字和一条低饱和黄色短线表达；其余项使用次要文字色，不填充整块背景。四项等宽，导航内容高度 60–64px，另计底部安全区域。再次点击当前页签不弹窗、不提交表单；浏览器前进、后退及页面刷新都应回到对应页面，切换页签时保留未提交草稿与合理的滚动位置。四个入口跨阶段保持稳定，可执行动作由资格决定；当前不能目击时，目击页说明原因与恢复条件。私密草稿只保留在当前会话内存，退出、换场或失去权限时清除，返回页面后重新确认资格。

“状态”页承担当前阶段、有效时钟、本人状态与当前主操作；“目击”页承担两侧手环选择、输入、核对和结果；“消息”页展示公开赛事事件与个人可见的系统通知，并按数据权限明确区分；“我的”页展示身份、本人现役配置、个人指标、记录与设置。阶段专属的广播、光粒和重生操作从相关页面中的明确入口进入独立流程页或可返回的全屏流程。

桌面保留相同信息架构，使用侧边导航或顶部导航进入同样的四个区域。裁判手机保留工作台与只读大屏的独立页面；设置若进入导航也必须有对应页面。搜索、审核、通知和暂停操作均可触控完成。

裁判桌面保持名册、所选文明详情和待办之间的关联。手机点击文明后进入完整详情，返回后保留列表筛选与阅读位置。

大屏有独立布局。返回工作台为导航动作；全屏为可选操作，数据查看与全屏模式分别工作。

## 4. 组件规范

共享 HTML 组件位于 `apps/web/src/components/ui.ts`，页面组合位于 `apps/web/src/pages/views.ts`。交互与路由位于 `apps/web/src/main.ts`。增加页面时优先组合已有组件。

### 4.1 操作组件

- `btn primary`：当前任务的主要动作，例如“进入比赛”“核对并继续”。
- `btn ghost`：返回、取消、查看等次要动作。
- `btn danger`：明确确认后的攻击或赛事控制操作。
- `text-button`：低强调度的辅助入口，仍保留足够点击高度。
- `icon-button`：关闭、全屏等熟悉且简短的操作，必须设置中文无障碍名称。

禁用按钮保持布局，配套文字说明当前未满足的条件。提交期间锁定操作。危险动作使用具体动词，例如“确认攻击”“确认执行”。

### 4.2 状态和反馈

状态优先使用清楚的文字；需要从列表中快速识别时，才补充小图标、短线或细描边。正常状态采用正文色，等待和限制可使用 `--yellow`，错误和危险可使用 `--red`。不使用有色实底标签，也不在每条状态前重复添加圆点。

持续影响比赛的状态进入主状态区，例如“暂时禁止攻击”“等待裁判核验资格”。短暂操作反馈使用简短提示，例如“已复制”。目击结果保留在目击页，提供后续动作和必要记录；用户离开确认对话框后仍可回到结果。

空列表区分无记录和搜索无匹配，搜索无匹配提供“清除筛选”。输入错误靠近字段或操作区展示。

### 4.3 手环选择与配置

两个集合始终称为“一侧手臂”和“另一侧手臂”。分别显示已选色块与数量，提供单个移除和整侧清空。左右互换、同侧重排保持相同含义。

可提交组合由 `validateArms` 校验。核对对话框同时展示两侧最终配置、当前操作后果及现场观察确认。点击色块只修改草稿。

本人正常航行时持续可查当前配置。返航或淘汰状态将配置标为失效。大屏与裁判详情按对应页面的读取范围展示配置。

配置优先用两组平面色环或色块直接呈现，并显示两侧数量。使用 HTML、CSS 或简单 SVG 表达真实配置，不绘制手部插画、立体手环、光照和辅助瞄准图。颜色标识 `BK` 等仅用于数据与代码，不显示为玩家需要记忆的缩写。

### 4.4 时间

时间采用等宽数字与冒号。标题明确写“有效比赛时间”。全场暂停和 98:00 核验暂停时冻结有效时间；界面使用 `PresentationClock` 保持展示连续。

后续接入服务时，有效比赛时间、真实时间期限和服务端状态分别处理。倒计时到期触发同步；阶段变化使用新的赛事快照。倒计时不设置逐秒播报。

### 4.5 对话框

使用原生 `dialog` 和 `showModal()`，带标题关联、关闭按钮、取消与确认区域。打开时进入对话框焦点范围，关闭后恢复触发位置。窄屏与长内容在视口内滚动，底部操作区保持可到达。

对话框用于当前页面内的确认、短说明和轻量选择。消息列表、本人信息、配置详情和完整规则等持续浏览内容使用页面。弹窗使用纯色背景及清楚边界，背景遮罩采用均匀暗化，不使用模糊、渐变和投影。

比赛控制采用“填写原因 → 预览影响 → 确认执行”。通知将复制和标记已发送分别设置为操作，复制失败展示可手工复制的完整文字。

## 5. 文案语言

### 5.1 直接表达

每句话说明当前事实、下一步或直接后果。按钮写明动作，字段写明对象，提示写明处理方法。所有页面使用自然、规范的汉语，禁止自创缩写、黑话、生造词和无用途的气氛文案。

界面不出现防御性写作，不添加“模拟数据”“不代表真实情况”等免责声明。不用预防质疑的附加句稀释操作信息。开发边界与验收记录放在工程文档。

禁止使用“A·B”“A·B·C”“A / B”“A / B / C”及同类变体串联关键词；不以改变空格或改用全角分隔符规避。并列信息使用独立字段，说明写成完整句子。文明编号与昵称直接用空格分开，例如“C07 远星”。路径、日期及有真实数值含义的比例使用各自格式，不属于关键词罗列。

不添加角落英文品牌字样、装饰编号、无功能的小字与副标题。例如“DARK FOREST”“当你凝视深空，深空也在凝视你。”都不进入界面。身份、比赛阶段、时间、错误原因和真实操作说明有明确用途，可以正常显示。

### 5.2 用词示例

| 使用               | 避免           |
| ------------------ | -------------- |
| 禁止攻击           | 禁攻           |
| 离开母星至少 50 米 | 离巢           |
| 领取手环配置       | 领码           |
| 击毁的不同文明     | 去重击毁数     |
| 累计识别错误       | 累计失配       |
| 等待裁判核验资格   | 门禁校验       |
| 填写暂停原因       | 填写操作上下文 |
| 请前往 QQ 发送     | 消息已经送达   |

文明、母星、光粒等已有玩法名称可以保留。内部枚举、请求标识和代码变量可采用工程命名，面向用户的标签采用自然中文。

### 5.3 风险提示

保留会改变玩家决定的具体后果，例如“第一次识别错误将禁止目击攻击 5 分钟”。提示只出现在相关操作处，同一流程避免反复堆叠。

## 6. 动效、资源与可访问性

使用不改变构图的短暂状态反馈，常规过渡控制在 120–160ms。页面背景保持纯色，不放天体、星点、轨道、纹理或持续动画。系统减少动态效果时取消非必要过渡和平滑滚动。

图标为统一的 24px SVG 几何线性图标，默认 1.5px 描边，常用显示尺寸为 20px。与相邻文字重复表达同一含义的图标设置 `aria-hidden`，有独立含义的按钮设置名称。不使用图片素材、CSS 插画、复杂符号堆叠或无功能装饰图形。

键盘焦点使用 `--blue` 的 2px 外框，向外偏移 2px。表单均有标签，复选框可点击完整说明，选色按钮设置 `aria-pressed`。中文色名保留在无障碍名称中。200%文字放大时，组件可换行。

相机、定位、照片上传与地图不属于网站交互。地点说明使用简洁文本，玩家在高德地图与 QQ 中完成线下协作。

## 7. 扩展示例与工程约定

### 新增玩家页面

复用 `shell` 与 `pageHeading`。先放置当前状态和主操作，再展开任务步骤。避免为了分组而把每个字段包进卡片。需要六位口令时使用字符串输入并保留前导零。完成后提供明确返回来源页面的入口。

### 新增裁判页面

延续名册筛选、记录详情、操作预览与回执的结构。桌面并行对照，手机顺序查看。重要状态持续展示，批量操作先汇总目标及影响。

### 新增大屏模块

保持大字号、紧凑说明和稳定列宽。沿用文明列表与时间线表达态势；读取字段由大屏模型提供，管理操作保留在裁判工作台。

### 本地开发

运行 `npm run dev:web`。现有前端包含首页、玩家状态、目击、裁判工作台和只读大屏五个 hash 路由，本轮没有改动代码。下一轮需要补齐独立的“消息”“我的”页面，把配置详情和公开事件从底部弹窗入口迁入相应页面，再按本文替换样式及文案。页面和子流程范围见前端页面规划。

运行 `npm test` 检查选择合法性、动作资格、时间暂停和页面数据范围。运行 `npm run check` 完成格式、Lint、类型和构建检查。视觉检查覆盖手机竖屏与桌面，截图和检查记录保存在本地 `.tmp/frontend-qa/`。

后续新增页面继续使用本地资源，保持现有 CSP。受保护的两份原始方案不随界面迭代改写，新增说明放在补充文档中。

### 改版验收

- 全站使用纯色背景、扁平几何图形和一致的细线；没有图片素材、渐变、纹理、阴影、发光与立体效果。
- 手环色之外没有鲜艳大色块；强调色只用于必要的小面积状态或交互标记。
- 首页、玩家页、裁判页、大屏和对话框都没有无功能的小字、副标题、口号或装饰编号，且遵守第五节文案规范。
- 手机底部四项均进入独立页面，当前页签、历史返回、刷新、草稿保留和安全区域行为正确；没有弹窗冒充一级页面。
- 状态页的首屏内容保持简洁，完整记录和消息进入各自页面；桌面裁判仍能并行对照名册、详情和待处理任务。
- 七种手环颜色从单一配置读取，视觉以颜色本身表达，辅助技术可以读取中文颜色名称与选择状态。
- 在 320、360、390、430、768、1024、1366、1920 CSS 像素宽度及 200% 文本放大下检查阅读、触控和键盘操作。新改版需重新验收，旧截图不作为新版通过的证据。
