# 赛前参数与正式名单补充

2026年11月4日用户确认，参赛人数可调整，歌者概率等参数提供配置入口，比赛期间保持固定。昵称区分拉丁字母大小写。本补充记录本次确认的规则，供后端实现与验收使用。

## 参赛人数与账号

预注册玩家账号构成候选账号池。总裁判在开赛准备或活动设置中选择正式参赛账号。参赛人数直接取正式名单长度，即 `N = len(正式名单)`；页面随选择显示人数及技术爆炸次数。

锁定统一发码时间 T0 时，正式名单中每人均完成母星审核及首航准备，此时冻结名单与比赛参数。T1锁定前由总裁判登记缺席、退出名单的处理沿用原方案，N随最终正式名单变化。未加入正式名单的账号不参与发码、统一激活、存活统计、技术爆炸抽取与正式排名。完整赛后复盘开放给本场正式参赛者。

锁定 T1 时，按正式人数计算技术爆炸次数：

`M = min(max(1, round(N/3)), floor((N-1)/2))`

2人场次为0次，12人场次为4次，24人场次为8次。秘密时刻在第8—55分钟生成并保存。人数容纳上限由350种首航配置的容量决定。

## 赛前参数

| 参数                                 | 默认值 | 配置单位 |
| ------------------------------------ | ------ | -------- |
| 歌者每完整分钟的首次清扫概率         | 5      | 百分比   |
| 第一次提交错误目击码后的禁止攻击时长 | 300    | 秒       |
| 第二次提交错误目击码后的禁止攻击时长 | 900    | 秒       |
| 第二次提交错误目击码后的淘汰概率     | 50     | 百分比   |
| 重生总时限                           | 900    | 秒       |
| 永久淘汰后等待观战的时长             | 180    | 秒       |
| 两次目击提交的最短间隔               | 4000   | 毫秒     |
| 滚动60秒目击次数上限                 | 10     | 次       |

总裁判在赛前预览修改内容并填写原因，确认后保存参数版本。T0锁定后，服务端拒绝参数变更，包括全场暂停期间。阶段边界和技术爆炸次数公式按原方案执行。玩家规则页、攻击确认提示和观战倒计时读取本场参数。

## 昵称与页面文字

昵称先做Unicode NFKC规范化并去除首尾空白，按可见字形计数2—8个字符，禁止控制字符与隐藏字符。唯一性区分大小写，`Alpha`和`alpha`可分别注册，`Ａlpha`规范化为`Alpha`。

用户可见文字沿用当前前端页面中的对应表达。新增文字使用规范汉语，例如“禁止攻击”“离开母星”“提交错误的目击码”。文档提供规则依据，页面文字从前端对应流程取用。
