## 关联规则的补充口径

1. 技术方案§9.2、§9.5、§9.7、§9.9的“已核验母星”限于本场冻结的正式名单。沿用[赛前参数与正式名单补充](赛前参数与正式名单补充_2026-11-04.md)的正式参赛边界，未被选入或赛前退出名单的母星不属于本场目标。仍在正式名单内的已淘汰者，其母星是否匹配继续由原有具体规则决定。
2. 技术方案§6.1、§16.4、§16.8的到期屏障增加受控故障例外：补结算失败时，授权裁判可以读取已提交状态，总裁判可执行故障暂停和事件处置。紧急暂停以服务器成功提交时刻冻结当前有效时钟，不伪造故障前暂停；失败事件及其他历史到期事件继续保留原计划时间，后续恢复仍须完成屏障，不静默跳过。
3. 资格恢复属于审计化纠错。原已出航飞船被人工误淘汰时，恢复不要求重新赋予母星生命，也不重新使用退役码；新保留配置须经裁判确认激活。暂停不赋予普通玩家临时攻防能力。已正式完赛的争议仍使用战报版本更正，不在本次增加重新开赛功能。
4. 用户已明确允许将原先设想由指令控制台承载的处置先通过管理界面和受保护HTTP接口完成。新增操作仍复用同一权威SQLite事务，不引入第二套比赛状态。

## 入口与数据升级

新写接口均先调用`POST /api/judge/manage/preview`，执行时携带预览Token、版本、稳定请求编号与原因：

| 方法 | 路径                          | 用途                                                                          |
| ---- | ----------------------------- | ----------------------------------------------------------------------------- |
| POST | `/api/judge/player-eliminate` | 记录正式开赛后的严重违规淘汰；正文包含`target`。                              |
| POST | `/api/judge/player-restore`   | 暂停后撤销错误淘汰；正文包含`target`。                                        |
| GET  | `/api/judge/events`           | 总裁判读取实际计划队列，包含状态、时基、原定时间、执行次数和诊断。            |
| GET  | `/api/judge/events/:eventId`  | 总裁判读取指定计划详情；ID按URL编码传递。                                     |
| POST | `/api/judge/event-control`    | 传入`event_id`及`operation=cancel/retry`。                                    |
| POST | `/api/judge/event-trigger`    | 当前实现手动歌者清理：`kind=song_visit`与六位`code`，须在第一阶段暂停后执行。 |

文明管理详情提供人工淘汰与恢复；赛事事件页提供计划详情、重试、取消和手动歌者；工作台显示调度故障告警，通知页分别展示复制与发送信息。操作记录支持按当前已加载记录中的操作者、文明、动作和原因检索，可分页补读历史。

业务Schema升级至6，迁移在同步事务内执行，保留原表数据。新增事件诊断字段、通知复制/发送字段及履历表、管理淘汰原态、预览影响和审计有效时间。旧版审计没有保存的前态无法补造，页面明确标记为历史缺失；旧通知没有复制/发送时间时保留空值。恢复检查点仍严格校验Schema版本，升级后应生成版本6的新检查点；本次未操作任何云端恢复或部署。

## 验证方式与边界

回归使用本地单元环境、真实workerd/SQLite及可控比赛时钟：实际React表单经过`HttpSource`交给共享严格Schema；独立真实HTTP网关测试将相同契约提交至DO。慢网回归挂载实际`AppProvider`，每次读取延迟3500毫秒并连续验证快照更新，同时验证离开页面后的旧响应不覆盖新状态。

后端覆盖候选母星隔离、默认及自定义重生期限、第一阶段/末日/终局人工纠错、持续故障注入后的读取/暂停/重试/取消、100条更新历史遮住旧待办、通知跨裁判复制与发送、业务预览和前后状态、事件幂等，以及旧Schema迁移和短时本地检查点恢复。测试中的65/98/120分钟等推进使用可控时钟，没有等待完整赛程。

不将组件传输桩与独立网关测试称为完整浏览器到DO的一体化验收。本次不运行完整两小时保全恢复或实时排练，不进行真实校园、校园网络、QQ、移动设备或实物手环验收，不据此宣称正式比赛生产验收完成。
