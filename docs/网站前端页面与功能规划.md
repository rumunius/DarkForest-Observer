# 《黑暗森林：观察者效应》网站前端页面与功能规划

编写日期：2026-11-03。

本文规划整站页面、功能、交互、信息权限、接口衔接和实施顺序。主要使用场景是玩家在竖屏移动端浏览器中参加比赛，裁判后台兼容手机并适合在电脑上连续工作。本文不规定美术风格、设计语言、字体、装饰、动效风格或通用界面配色，也不包含已实现页面。七色手环的色值属于游戏物料配置，单独统一管理。

### 1.3 前端职责

网站负责让用户知道当前状态、找到当前可用功能、完成输入、确认操作并取得结果。比赛阶段、攻击结算、重生期限、资源数量、名次、观战资格和裁判权限均由服务器确定。

照片通过QQ发送；现场导航在玩家自己的高德地图软件完成；终局位置共享在QQ群完成。网站提供相应步骤说明、已保存信息生成的复制消息、审核结果和人工裁决记录。

## 2. 用户与整站结构

### 2.1 使用空间

| 使用空间 | 使用者                   | 主要任务                                                 | 主要设备                     |
| -------- | ------------------------ | -------------------------------------------------------- | ---------------------------- |
| 进入比赛 | 已获参赛口令的玩家和裁判 | 登录、了解活动、进入所属工作空间                         | 手机和电脑                   |
| 玩家页面 | 参赛玩家                 | 母星登记、首航准备、目击、广播、光粒、重生、查看本人信息 | 竖屏手机                     |
| 宇宙观测 | 永久淘汰满180秒的玩家    | 查看当前全局战况、文明详情和历史事件                     | 竖屏手机                     |
| 裁判后台 | 持独立裁判账号的工作人员 | 审核、开赛、通知、终局核验、纠错和赛事管理               | 电脑为主，手机可完成现场工作 |
| 观战大屏 | 已登录裁判打开的只读展示 | 展示文明状态、比赛时间和已发生事件                       | 外接显示器                   |
| 赛后复盘 | 本场全部参赛者及授权裁判 | 查看正式名次、完整战报、文明历史和事件过程               | 手机和电脑                   |

不增加开放注册、公共匿名观战、玩家聊天、在线交易、网页投票或校园导航。四维观察者向裁判提出建议的流程在线下完成。

### 2.2 玩家导航

玩家主导航固定为四个入口：**当前、行动、消息、我的**。入口始终可直接触达；页面根据比赛状态调整内部内容，不因阶段变化反复更换导航名称。

| 入口 | 默认内容                                   | 二级页面                                                         |
| ---- | ------------------------------------------ | ---------------------------------------------------------------- |
| 当前 | 比赛阶段、本人状态、相关倒计时、当前下一步 | 母星登记、首航准备、重生、终局说明、淘汰等待、宇宙观测、赛后复盘 |
| 行动 | 当前合法行动的入口；合法时优先显示目击输入 | 正式广播、光粒发射、操作结果                                     |
| 消息 | 本人消息与已公开赛事消息，按标签切换       | 消息详情、正式广播详情、已获母星情报                             |
| 我的 | 文明身份、本人手环、母星状态、个人战绩     | 手环详情、规则、联系裁判、异常申报、账号、退出比赛               |

“当前”承担流程引导，“行动”承担比赛操作。首航、重生等需要依次确认的流程进入独立页面；完成后回到对应主入口。收到状态变化时保留有权阅读的历史内容；已失去资格的行动入口、表单、资源操作卡与确认区整体移除，改为当前状态及下一步，不仅禁用提交按钮。

### 2.3 页面切换与滚动

1. 默认按一个主要任务组织一个页面。主导航、页内返回和主要操作按钮不放在长内容末尾。
2. 目击输入、领取手环、确认佩戴等短操作优先在常见竖屏首屏完成。输入项过多时，先移走次要说明，再拆分独立任务，不缩小触控目标或压缩文字。
3. 事件列表、比赛规则、完整战报、长表单和详情正文正常纵向滚动。列表加载更多或常规分页都可使用，不把每条消息改造成强制翻页。
4. 浏览器返回遵循页面历史；从详情返回时恢复原列表位置。主导航之间切换时保留该入口的阅读位置和未提交输入。
5. 不靠左右滑动作为唯一的功能入口，不设置无限横向标签栏，不要求通过横屏完成玩家操作。
6. 屏幕较矮、字体放大或软键盘打开时允许纵向滚动；不以截断内容换取首屏完整。
7. 网页打开后即可使用，不要求安装应用。浏览器地址栏变化、底部安全区、软键盘和手机切换到QQ后的恢复均列入验收。

### 2.4 电脑适配

玩家页在电脑上沿用同一内容和操作顺序，可将状态摘要与当前任务并列，避免把手机页面无限拉宽。裁判后台使用固定功能导航、列表和详情联动；手机上将列表与详情分为前后两页。大屏为独立只读路由，不复制裁判后台作为投影内容。

## 3. 页面清单与访问条件

### 渐进式披露总则

本节按2026-11-03用户要求统一前端披露规则；与本文件其他段落中的笼统“禁用”“关闭提交”冲突时，以此处及[设计系统§6.4](网站前端设计系统.md#64-渐进式披露)为准。它细化显示方式，不修改服务器允许动作、游戏处罚与信息权限。

| 类型 | 触发逻辑 | 本站应用 |
| --- | --- | --- |
| 分步式 | 当前步骤完成且服务器确认前置条件后，进入下一步 | 母星登记、首航、重生只显示当前步骤的输入和操作；已完成步骤收为可主动查看的只读摘要；未来步骤不提前展示表单、配置或禁用按钮 |
| 条件式 | 用户明确请求更多内容 | 点击查看规则、操作详情、历史记录、筛选条件、显示颜色名称时才展开；再次关闭返回摘要；展开不能绕过权限 |
| 情境式 | 当前阶段、本人状态、资源、限制、输入及服务端允许动作改变 | 仅显示此刻适用的行动；被击毁隐藏目击、广播和光粒操作，正常出航隐藏领码和重生操作；输入有效后才出现最终确认动作 |

固定导航是找回当前任务、消息和个人信息的稳定结构，不是全功能目录，继续使用“当前、行动、消息、我的”。没有任何合法比赛行动时，“行动”只显示当前原因及返回当前任务的入口，不展示灰色行动卡或未来功能列表。规则、联系裁判、账号及有权查看的历史仍可主动进入；“不能使用当前行动”不等于删除已发生消息或禁止查看本人记录。

所有行动入口、快捷按钮、深层链接、消息详情中的行动按钮和个人页均遵守同一披露条件。隐藏内容不占空卡片、不留禁用轮廓、不进入键盘及读屏顺序；直接访问不适用的操作地址，只显示原因和当前可用去向，不渲染旧表单。最终权限始终由服务端核验。

当前合法任务内的输入校验与请求等待不等于失去玩法资格：未填写完整时保留必要输入，暂不显示最终提交动作；显示具体完成要求，不自动提交。提交中或结果未知时显示原请求摘要和查询进度，防止重复提交。断线时保留草稿及连接反馈并暂停提交，不把断线误判为永久失去资格。

### 玩家状态与披露矩阵

以下是呈现条件，不能只按阶段单字段判断。先检查会话和资格，再检查完赛、淘汰、当前流程、全场暂停、阶段、个人限制及资源；多个条件并存时取服务端允许动作的交集。任何表中行动仍须有服务端授权。

| 当前情境 | 显示的任务和操作 | 不显示的操作UI |
| --- | --- | --- |
| 未设置昵称、未登记或待审核 | 当前身份或登记步骤、保存结果、当前需要的QQ材料及审核状态 | 首航领码、佩戴确认、目击、广播、光粒、重生 |
| 首航准备、尚未到发码条件 | 当前准备任务或发码等待说明 | 领取按钮、未发行配置、佩戴确认及战局行动 |
| 允许领取首航配置 | 领取说明及领取按钮 | 领取成功前的具体手环、佩戴确认和攻击操作 |
| 已领取、尚未确认佩戴 | 当前两臂配置与确认穿戴就绪 | 再次领码、攻击、广播、光粒 |
| 已就绪、等待正式开赛 | 开赛等待及只读本人配置入口 | 领码、重复就绪确认及战局行动 |
| 第一阶段正常出航 | 目击；广播仅在有余量时出现；光粒仅在持有可用库存时出现 | 领码、佩戴确认、重生；零余量的广播、零库存的光粒操作 |
| 仅个人禁止目击、仍正常出航 | 禁止目击的原因、剩余时间及仍会被击毁的说明；其他有资格的行动 | 目击色盘、输入、确认按钮；不因禁目击而误删仍合法的广播和光粒 |
| 飞船被击毁、尚未完成重生 | 摘环要求、统一截止、当前重生步骤；相应步骤才出现QQ复制、领新码或完成出航 | 目击、正式广播和发射光粒的入口、表单与确认区；后续重生步骤的操作 |
| 母星毁灭但仍出航 | 最后一命、当前阶段仍允许的行动 | 重生、领码；不能仅凭母星毁灭就提前隐藏第一阶段仍合法的广播或光粒 |
| 65分钟后仍出航 | 目击及当前相关状态 | 广播、光粒、重生、领码 |
| 转场或终局资格核验 | 当前QQ步骤、期限或核验等待 | 目击及全部不合法战局操作，不提前显示恢复攻击按钮 |
| 最后狩猎已获准且未暂停 | 目击、相关有效时间、QQ共享要求 | 广播、光粒、重生、领码 |
| 全场暂停 | 暂停原因、冻结的相关期限、可读状态和仍合法的只读入口 | 所有改变正式战局的普通玩家操作，包括重生推进；恢复后重新取权限再显示 |
| 永久淘汰未满180秒 | 摘环、返回裁判室、等待、个人记录 | 战局操作、重生、领码、提前进入观战按钮与全局详情 |
| 永久淘汰满180秒 | 经服务器确认后的宇宙观测入口与本人记录 | 正式比赛行动及裁判操作 |
| 比赛结束 | 正式结果、完整战报和授权复盘 | 比赛行动、领码、重生、已不适用的等待及倒计时 |

情境式隐藏针对操作与不相关的当前任务，不抹除真实历史。返航时收到光粒消息仍可阅读，但没有发射入口，正文写“已获得光粒1枚”，不将库存称作当前“可用”。具体库存、历史配置和长规则放在用户主动进入的详情中；正常出航时可查看本人现役手环，但只读配置不带领码按钮。

无论采用哪种披露，当前任务的截止时间、当前限制、不可逆后果、攻击错误后果和必须执行的现场步骤不能藏在折叠项中。只隐藏与当下无关的步骤与操作，不隐藏作决定必须知道的事实。

路径是实施时的建议结构，页面名称才是界面文案。路由中的英文不直接展示给玩家。每个路由支持直接打开、刷新和浏览器返回。

### 3.4 共用页面状态

所有空间提供加载、连接中断、会话失效、无查看权限、内容不存在和服务暂时不可用的页面状态。默认提供一个明确的恢复动作，例如重新连接、重新登录或返回所属空间，不把技术错误堆成一整页。

未登录打开业务深层链接时先登录，再检查是否有权进入原页面；已无资格的行动链接回到本人当前状态。不存在的网页显示真正的页面未找到状态；不存在的接口返回对应接口错误，不回退成登录页或应用HTML。退出登录后不让浏览器返回恢复秘密内容。

赛前从正式名单退出的玩家看到参赛安排与联系裁判入口，不显示比赛中的淘汰排名。无关场次的记录不混入当前比赛。报名口令、场次和角色由服务器确定，页面不提供任意选择身份的下拉框。

## 4. 玩家页面与功能

### 4.1 进入比赛、登录与昵称

进入页首屏只放活动名称、简短参与说明、玩家登录和裁判入口。活动说明用普通文字介绍玩法，不展示赛事秘密或未经授权的全局列表。活动时间、QQ群信息采用本场配置，不写死示例日期和校园名称。

登录页提供一个完整口令输入框，支持粘贴、显示或隐藏输入内容、提交状态和明确错误提示。成功后根据会话进入玩家页或裁判页，已有会话再次打开网站直接恢复原空间。凭证失效时回到登录，显示“请重新登录”。

玩家首次设置昵称时显示文明编号、昵称输入和确认预览。采用策划案建议的2—8个汉字或等长字符，最终字符计算和唯一性校验由公共契约统一。提交前说明“确认后昵称将固定”，按钮写“确认昵称”。保存后进入母星登记。已锁定昵称不再显示编辑框；需要更正时从联系裁判办理。

首屏从上到下显示比赛阶段、本人当前状态、当前最相关的倒计时、一项主要任务和不超过两项关联入口。完整规则、历史和次要统计移到独立页面。

| 本人及比赛情况    | 主要内容                                   | 主要操作           |

### 4.3 母星登记

采用“填写口令—保存登记—发送QQ材料—查看审核”流程。口令用一个六位数字文本输入框，弹出数字键盘，允许一次粘贴完整内容，保留前导零；不设计六个彼此独立的小输入框。

保存成功后展示服务器已保存的口令、提交版本和“待审核”。此时才提供“复制登记消息”，正文来自服务器已保存版本。复制成功提示“已复制，请到裁判QQ私聊粘贴并附上现场照片”。剪贴板不可用时展示可长按选择的完整文本。

待审核期间可按服务器允许的条件修改口令并重新提交；新版本保存后提示重新发送最新登记消息和照片。通过后显示“母星已登记”，进入首航准备。退回修改时展示裁判具体原因和“重新填写”。页面不上传照片、不打开地图、不校验高德中的地点。

### 4.4 首航准备

将发码与开赛分成清晰的步骤。玩家端以“发码时间”“开赛时间”表达，不把T0、T1当作玩家必须理解的界面术语。

| 步骤     | 页面内容                                                                       | 提交行为                                 |
| -------- | ------------------------------------------------------------------------------ | ---------------------------------------- |
| 准备     | 确认已离开母星至少50米；显示七色色块，核对七种手环各一条；当前尚未佩戴比赛配置 | 点击“准备完成”，服务器确认进入待发码状态 |
| 等待发码 | 发码倒计时；尚未安排时间时显示等待说明                                         | 到时刷新状态后显示领取按钮，不自动发行   |
| 领取配置 | 领取说明；服务器确认发行后才展示两臂色块并进入佩戴步骤                         | 点击“领取手环配置”，重复请求返回同一份   |
| 佩戴     | 指定的3或4条手环、其余收入口袋说明                                             | 点击“确认穿戴就绪”                       |
| 等待开赛 | 已穿戴就绪状态、统一开赛倒计时                                                 | 服务器确认开赛后自动进入比赛状态         |

图示允许整体交换两臂，交换只改变展示顺序，不重新发码，不增加佩戴顺序要求。每个步骤刷新后由服务器状态恢复，不让玩家重复完成已提交动作。准备码在正式开赛前不提供攻击入口；开赛后需重新现场观察目标。

### 4.5 行动页与目击攻击

有目击资格时，“行动”默认进入图形输入。正式广播和光粒是明确的独立入口；两者只在服务器允许的阶段与状态出现。当前暂时不能目击时显示原因，仍合法的广播、光粒可以直接进入。65分钟后移除广播、光粒和重生操作入口，既有记录留在消息及个人历史中。

目击页由两组七色按钮、当前选择结果、错误提交累计次数、下一次错误提交的实际后果和“确认攻击”组成。手机竖屏将两侧选择区上下排列，每组采用能保证触控面积的换行布局；不强行把十四个按钮排成一行。

交互规定：

1. 两组名称为“一侧手臂”“另一侧手臂”。点选色块立即在对应组预览；再次点击可取消。
2. 同一种颜色只能出现一次。在另一组已使用时，该组对应按钮显示已被另一侧选中，不自动把颜色移动过去。
3. 两侧数量符合两条与一条、两条与两条或三条与一条时允许提交；两臂交换等价，同臂没有顺序。非法组合只给出具体输入说明，不发起攻击。
4. “清空选择”清除本次未提交内容。“交换两侧”只交换展示，不改变实际组合。
5. 不提供目标文明输入、姓名搜索、拍照识别、历史攻击一键重发或候选码推荐。
6. 最终颜色与下一次错误提交后果在按钮附近可见，点击“确认攻击”即为最终确认，不再增加多层确认弹窗。
7. 提交期间锁定本次输入和按钮。网络结果未确定时显示“正在确认攻击结果”，查询原结果或以同一请求编号重试；得到明确结果后才允许新攻击。
8. 一次攻击完成后清除攻击输入，不将历史颜色自动带入下一次攻击。成功获得的母星口令进入本人情报记录。

| 当前累计提交错误目击码的次数 | 确认区显示的后果                                                             |
| ---------------------------- | ---------------------------------------------------------------------------- |
| 0次                          | “提交错误的目击码，将禁止目击攻击5分钟。”                                    |
| 1次                          | “再次提交错误的目击码，有50%的概率永久淘汰，有50%的概率禁止目击攻击15分钟。” |
| 2次                          | “再次提交错误的目击码，将永久淘汰。”                                         |

攻击结果按服务器结算展示：

| 结果                       | 页面反馈                                                     | 后续入口               |
| -------------------------- | ------------------------------------------------------------ | ---------------------- |
| 击毁成功                   | “已击毁目标飞船”，目标编号和昵称、六位母星情报、本人最新战绩 | 查看母星情报、返回行动 |
| 未产生击毁，错误次数未增加 | “本次目击未产生击毁”，本人累计错误次数                       | 返回行动               |
| 错误提交后暂时禁止攻击     | 同一未击毁文案、最新错误次数、实际剩余时间                   | 当前页、其他合法行动   |
| 错误提交导致永久淘汰       | 未击毁结果和“你已永久淘汰”，摘环与返回裁判室安排             | 淘汰后安排             |
| 阶段或本人状态已变化       | 具体原因，例如“已进入转场，目击攻击暂停”                     | 当前页                 |
| 请求过于频繁               | 服务器给出的可重试时间，例如“请在4秒后再试”                  | 到时恢复输入资格       |

普通玩家不会从未击毁提示中获知该配置是否属于自己、历史航次、尚未激活的配置或未发行配置。累计次数、处罚和淘汰结果由服务器返回，前端不把所有未击毁都算成错误提交。

个人被暂时禁止目击攻击时，状态说明写“你仍在出航，可以被其他玩家击毁”，并显示仍可执行的其他行动。规则后果在相关位置说明一次，不在每个按钮前重复弹出提醒。

### 4.6 正式广播

页面显示剩余次数、单个六位口令输入框和本次确认摘要。可以从本人已获得的母星情报进入并带入该口令，也可以输入任意合法六位数字。输入时只检查格式和已公开广播记录，不判断真实母星归属。

提交前用直接文案说明：“广播将公开这组六位口令，并消耗1次广播次数。若它对应某个文明的母星，该文明会获得你的母星口令。”同时可从规则说明了解歌者的每满60秒检定规则，不显示预计清理时间。

成功显示“广播已发布”、广播内容与剩余次数；重复广播显示“这组六位口令已被广播”，并可查看公开记录。不公开坐标对应文明，不因为真假或母星是否仍存而改变成功文案。

### 4.7 发射光粒

本人获得光粒时收到私人消息；当前有发射资格时才显示可用库存与发射入口。返航途中获得光粒仍可阅读“已获得光粒1枚”的历史通知，但不显示发射卡片、表单或按钮；完成出航后重新核验阶段、暂停状态与库存，再决定是否出现发射入口。

发射页显示库存、六位口令、确认摘要及“发射光粒”。提交前写“发射将消耗1枚光粒”，不预先鉴定坐标是否存在母星。成功先显示“光粒已发射”，再展示与该事件关联的公开结算结果；不对结果进行客户端猜测。

赛中普通玩家看到的公开事件隐藏发射者，永久淘汰满180秒的观战玩家与有相应权限的裁判可查看发射者。65分钟后未使用光粒失效，个人历史可以记录曾获得与未使用的数量，行动页不再显示发射按钮。

### 4.8 重生

只有服务器返回可以重生的状态时显示本流程。顶部持续显示“距离重生截止”及剩余时间；实际截止是被击毁后15分钟与比赛65:00中更早的一个，所有步骤共用，必须严格早于截止完成出航。

| 步骤     | 玩家看到的内容                         | 操作和完成条件                                     |
| -------- | -------------------------------------- | -------------------------------------------------- |
| 返回母星 | 摘下全部比赛手环、正常步行返回母星     | 查看本人母星口令；自行使用高德地图                 |
| 发送照片 | 母星现场时间水印照片说明、本次航次消息 | 复制消息，前往QQ发送文字和照片，再点击“已发送照片” |
| 离开母星 | 保持不佩戴手环，离开母星至少50米       | 点击“已离开母星，领取新配置”                       |
| 重新佩戴 | 新的两臂色块、佩戴数量及剩余时间       | 核对后点击“完成出航”                               |
| 出航完成 | 服务器确认的状态和现役配置             | 返回行动页                                         |

发送照片后按服务器结果进入下一步，不增加逐次等待裁判批准的流程。翻回上一页只能查看材料和状态，不能撤销已完成的服务器步骤。

中途母星毁灭、期限到达、65分钟到达或比赛提前结束时，立即停止本次提交并转到对应结果。全场暂停时冻结重生时间和战局提交。个人暂时禁止目击攻击的时间单独显示，重生不将其清零。

### 4.9 终局说明

赛前及65分钟后可阅读终局要求；90分钟以前不要求玩家提前开启共享。90分钟开始，当前页显示以下明确步骤：

1. “加入比赛QQ群的实时位置共享。”
2. “查看QQ群文件中的终局圈图片，使用手机高德地图前往。”
3. “在比赛时间98:00前进入终局圈，并保持位置共享。”

页面显示8分钟转场的剩余有效时间。玩家无需在网站点击“已入圈”或“已共享”；网站不制造此类状态。98:00显示“终局资格确认中”，比赛计时停在98:00，等待裁判完成核验。获准继续比赛后恢复目击，显示剩余有效时间和“请持续共享位置”。资格被取消时显示本人的裁决结果和淘汰后安排。

### 4.10 淘汰后安排

显示淘汰原因、服务器记录的生效时间、本人战绩以及实际剩余观战等待时间。主文案：“请摘下全部比赛手环，步行返回裁判室。裁判室位置请查看QQ群文件。”比赛中曾参加位置共享的玩家同时得到“可以停止位置共享”的提示。

等待时间从服务器记录的永久淘汰生效时刻起计算，满180秒后刷新资格并显示“进入宇宙观测”。如果裁判较晚确认98分钟淘汰，按生效时间计算，不能从玩家打开页面或收到通知时重新等3分钟。

在规则说明中直接表达“观战信息仅供已淘汰玩家交流，请勿向仍在比赛中的玩家传递”。若裁判恢复本人参赛资格，关闭观战页面并清除其全局数据，回到修正后的玩家状态。

### 4.11 消息、情报与个人页面

消息页使用“本人消息”“公开事件”“正式广播”三个标签；未读数量来自本账号阅读状态，不暗示QQ是否送达。列表可按时间滚动，打开详情再返回保留位置。新增消息以“有新消息”入口提示，不在阅读历史时强制滚动到顶部。

本人消息覆盖审核、首航、被击毁、母星毁灭、技术爆炸、广播带来的情报、裁判提示和淘汰结果。消息详情显示发生时间及来源；需要操作时提供当前仍合法的页面入口。过时按钮转换成查看结果。

母星情报只保存本人通过成功目击或合法广播反向情报获得的记录，说明获知时间和来源。已知的状态标明是获知时状态；后续只随本人有权读取的公开事件或私人通知更新，不把他人当前秘密状态实时补给玩家。口令可复制，历史情报不提供查询任意文明母星的功能。

个人页包含文明编号、昵称、当前飞船状态、本航次手环配置入口、本人母星、个人战绩、规则、联系裁判和账号。正常出航仍可查看当前手环色块；被击毁后原配置进入历史并标明失效，不冒充现役配置。

战绩名称使用“已击毁的不同文明数”，详细说明“同一文明被多次击毁只计一次”。完整个人记录按事件列出，不把广播、光粒或歌者造成的母星毁灭计入此数。比赛中不向仍在比赛的玩家展示全场战绩排名。

### 4.12 异常申报、退出登录与退出比赛

异常申报选择明确类别，如手环损坏、网页无法提交、攻击结果需要复核；消息由服务器根据本人已保存状态、相关事件和时间生成。玩家复制后通过QQ发给裁判，可另写情况说明，不在网站新增照片上传或工单审批系统。

“退出登录”只结束会话，不改变参赛状态。“退出比赛”位于账号页的独立流程，显示“确认退出后，你的文明将永久淘汰”，最终按钮写“确认退出比赛”。等待服务器确认后进入淘汰后安排。赛前缺席由裁判在名册管理处理，不混同正式淘汰；全场暂停等不可执行状态遵循服务端允许的动作。

### 4.13 比赛规则

规则页按“比赛流程”“手环与目击”“母星与重生”“广播与光粒”“终局要求”“淘汰后观战”“排名与现场要求”组织阅读目录。每个主题是正常可滚动的文章，目录定位到对应标题；不把每一条规则拆成必须逐页点击的卡片。

玩家从具体操作进入规则时直接定位相关章节，阅读后返回原表单并保留未提交输入。正文使用本规划的规范文案，保留原规则的具体条件和后果；示意只使用两臂颜色集合，不绘制场地区域。

手环章节解释现场亲眼观察、两臂互换等价、同臂无序、完整摘环和当前配置的含义；时间章节解释比赛暂停与个人等待的差别；终局章节引导查看QQ群文件与自行使用高德地图；现场要求直接说明正常步行、不得干扰他人和观战信息交流范围。页面不使用免责套话代替清楚的比赛规则。

## 5. 宇宙观测、观战大屏与赛后复盘

### 5.1 宇宙观测

“四维观察者”是原玩法中的正式身份；页面首次进入时说明其含义：“你已永久淘汰，可以查看当前战况和已经发生的赛事记录。”使用“战况”“文明”“事件”“我的”四个固定入口，保留返回本人页面的路径。

| 页面     | 内容                                                                               | 交互                                           |
| -------- | ---------------------------------------------------------------------------------- | ---------------------------------------------- |
| 战况     | 比赛阶段、有效时间、暂停状态、存活数、已淘汰数、尚存母星数、当前资源统计           | 进入文明列表或对应事件；统计只取服务器已确定值 |
| 文明     | 全部文明的编号、昵称、飞船状态、母星状态及已产生战绩                               | 按编号或昵称查找，按状态筛选；列表自然滚动     |
| 文明详情 | 已审核母星口令、现役两臂色块、广播余量、光粒、重生剩余时间、历史航次               | 切换“当前状态”“航次记录”“相关事件”             |
| 事件     | 已发生攻击、错误提交处罚、重生、正式广播、歌者、光粒、技术爆炸、人工裁决及阶段事件 | 按事件类别、文明和时间筛选，查看详情           |
| 我的     | 本人的名次待定状态、战绩、淘汰时间、返回裁判室说明                                 | 联系裁判、查看规则、退出登录                   |

比赛仍在进行时不把当前统计称为最终排名。光粒发射者、技术爆炸获得者和已发生的秘密情报授予可以在观战详情中显示。未来歌者清理时间、未来技术爆炸安排、随机抽签原始值、登录凭证、QQ照片和裁判管理记录不进入这些页面。

观察者看到的手环同样以两臂色块展示，不能仅显示颜色编号。详情可解释历史航次，但不提供向仍在比赛的玩家转发、分享秘密或执行操作的按钮。

### 5.2 观战大屏

裁判从工作台点击“打开观战大屏”，在同一浏览器的新标签页打开，再移到外接显示器。大屏通过独立只读数据入口读取与宇宙观测相同范围的赛事数据，使用现有裁判会话鉴权。

大屏包含“全场概况”“文明状态”“赛事事件”“比赛结果”四种展示页。大屏首屏显示当前阶段、时间、存活数和与选定页面有关的内容；列表超出屏幕时使用普通分页或可关闭的自动轮播，不把24名文明强行缩小到难以阅读。自动轮播仅适用于无人操作的展示场景，移动端仍使用普通列表。

大屏不显示裁判导航、审核按钮、待发送私聊内容、命令输入、调度计划或浏览器通知中的秘密。断线显示“正在重新连接”，保留最近一次已读取数据及更新时间；会话失效后清除赛事详情并显示“请由裁判重新登录”。

大屏只读描述的是页面和接口能力；它仍运行在裁判已登录浏览器中，不把该浏览器交给观众操作，不宣传为独立低权限账号。裁判工作台与大屏各自保持页面状态，互不抢占当前视图。

### 5.3 比赛结果与完整复盘

只在服务器确认比赛结束后进入正式结果。首页显示结束原因、冠军情况、本人名次及“完整名次”“赛事战报”“文明复盘”入口。比赛提前结束时不继续显示120分钟倒计时，也不强制延迟复盘。

名次直接使用服务器给出的排名与并列组：幸存者排在淘汰者之前；幸存者按击毁的不同文明数排序；淘汰者按有效淘汰记录排序。全体淘汰时写“本场没有存活冠军”，不把榜单第一项额外标为冠军。并列使用“并列第1名”等完整表达。

完整战报展示正式事件时间线，可按文明与类型筛选。文明复盘包含母星六位口令、各航次手环配置及生效和失效时间、攻击结果、资源获得和使用、重生、淘汰及与其有关的纠错结果。只展示已发生事实，不展示未执行随机计划、原始抽签值或认证秘密。

全体本场参赛者可访问上述完整复盘，包括幸存者与刚淘汰未满3分钟的人。赛前退出正式名单者不自动获得本场完整秘密复盘权限；匿名访客不开放完整记录。正式公共战报与带秘密历史的复盘采用不同数据入口，不能把后者直接塞进公共排名响应。

手机端以摘要和详情页面组织，长时间线正常滚动。电脑端可并列显示文明和对应历史。裁判完成赛后纠错时，显示更新后的正式结果，并保留相关更正说明和报告版本。

## 6. 裁判后台

### 6.1 导航与工作台

电脑端固定主导航，页面按任务分组：

- 赛事工作：工作台、母星审核、开赛准备、通知待办、终局执裁。
- 状态与记录：文明管理、赛事事件、攻击复核、比赛结果。
- 比赛管理：比赛时间、手环处理、临时效果、指令控制台。
- 系统管理：系统状态、操作记录、活动设置、裁判账号。

手机端固定“工作台”“待办”“文明”“更多”四个入口，重要任务和总裁判暂停入口不需要滚动长菜单才能找到。“待办”聚合待审核母星和待发送通知，切换后进入对应任务列表。“更多”使用常规菜单，二级管理页支持返回。

工作台首屏显示阶段、比赛时间、暂停状态、正式参赛数、存活数、母星待审核数、首航进度、未发送通知和需要处理的系统异常。每个数量都能进入相应列表。通讯裁判优先看到审核和通知，事件裁判优先看到事件与通知，总裁判优先看到开赛、时间、终局与异常。

发生需要裁判介入的情况时使用具体信息，例如“剩余手环配置10组”“有3条淘汰通知待发送”“有2个到期事件尚未结算”，不以抽象技术代号代替任务。手机和电脑均可执行职责内常用操作，复杂指令可在电脑上提高信息密度。

### 6.2 母星审核

待审核列表显示文明编号、昵称、六位口令、提交版本、提交时间；点击进入详情。电脑可并列显示列表和审核详情，手机逐页进入。

详情要求裁判在QQ和高德地图软件中核对当前口令版本、照片、地点和母星互不重复的要求。网站只显示待审核记录和审核输入，不嵌入照片或地图。操作为“审核通过”“退回修改”；退回时填写具体原因。

提交携带裁判正在查看的口令和版本。若玩家已经重提、其他裁判已经处理或比赛状态改变，停止当前确认，显示“这条登记已更新，请核对最新版本”，加载最新记录后由裁判重新判断。不自动沿用对旧版的批准。审核成功显示操作者、时间和当前状态。

### 6.3 开赛准备

名册按文明列出母星审核、离开母星确认、七种手环核对、领取配置和穿戴就绪进度。逐项使用自然语言状态，不显示原始状态枚举。详情可查看已发行的准备配置和相关记录。

发码操作前展示未完成准备的人员；全部正式人员准备完成后，总裁判设置未来发码时间并确认名单。T0生效只允许玩家领取配置，不显示为已经开赛。

所有正式玩家穿戴就绪后，总裁判设置未来开赛时间，预览人数和倒计时再确认。服务器确认锁定后展示统一倒计时；只有服务器确认开赛，后台才显示“比赛进行中”。

不能参加者从名单详情进入“登记缺席”，显示该人员退出正式名单的影响和已发配置的处理结果；已发行配置永久退役，不回到可用数量。发码前名单锁定与开赛前处理缺席分别遵循原接口条件，页面不增设任意添加正式玩家或跳过准备的快捷按钮。

### 6.4 通知待办

分别提供“群公告”“玩家私聊”标签和“待发送”“已复制”“已发送”“需要处理”筛选。失联、重生期限和永久淘汰通知优先；每条显示目标、事件类型、发生时间、当前状态和处理人。

详情展示服务器生成的准确正文。裁判点击“复制消息”只记录复制；实际在QQ发送后再点“标记已发送”。也允许裁判已经发送后直接标记。发送遇到问题时点击“记录发送异常”，填写原因，后续可重新处理。

不同裁判同时处理同一条通知时，详情展示最近操作者和服务器最新状态，状态变更使用版本校验或等价条件写入。旧列表中的按钮不能覆盖新状态。复制失败时提供选中文本，且不提前记录复制成功。

通知和QQ发送是两件事：页面分别记录发生时间、复制时间和发送时间。秘密字段只进入正确收件人的文本。空坐标歌者事件按原规则允许合并播报，真实母星毁灭与光粒结果分别处理，不自动合并所有消息。

### 6.5 文明管理

列表按编号、昵称搜索，按赛前准备、出航、返航、准备重生和永久淘汰筛选。详情用“当前状态”“手环航次”“比赛记录”“通知”“裁判操作”组织，长记录保持滚动。

授权范围内显示本人母星、资源、当前两臂色块、错误提交累计、禁止攻击剩余、重生期限与淘汰记录。敏感字段按职责返回，普通通讯职责不默认获得所有随机抽签明细。

修改昵称、恢复资格、修正资源、修正母星或异常状态均进入对应管理操作，展示当前值、拟变更值、原因及相关影响后提交。通常操作以表单完成，长尾情况链接到预填目标的指令控制台；不在列表内提供任意改写生死状态的简单开关。

### 6.6 终局执裁

90分钟开始显示待核对的存活文明名单。裁判继续在QQ群查看共享位置，网站提供人员选择和裁决，不显示地图、定位点或“实时在线位置”状态。

98分钟到达后，后台显示“终局资格核验中”，比赛时间停在98:00。总裁判逐人核对后，在一份待提交名单中选择需要淘汰的文明，为每人选择“未按时加入位置共享”或“截止时未进入终局圈”。这只是本次裁决草稿，不存储位置快照，也不在选择时逐人淘汰。

“完成核验”前展示全部淘汰对象、各自原因、预计保留人数和可能的结果。可以提交空淘汰名单。最终请求一次提交整批名单，服务器同批结算；至少两名文明存活时开始最后狩猎，只剩一名或无人存活时直接完赛。

若名单在其他裁判操作后变化，刷新并重新核对，不将过期草稿无条件重放。提交期间禁止再次提交；结果不明时恢复原请求结果，不创建第二批淘汰。

核验暂停只能由“完成核验”结束，普通恢复按钮显示“请先完成终局资格核验”，不能绕过。最后狩猎期间改为单人执裁流程，原因是“离开终局圈”“停止位置共享”或“定位违规”；确认后按服务器实际提交时刻生效。

### 6.7 比赛时间与临时效果

比赛时间页同时说明当前有效比赛时间、真实本地时间和暂停情况。全场暂停输入原因并确认，成功后状态才改变；断网、按钮点击或浏览器卡顿不显示为已暂停。恢复后刷新阶段、剩余时间及所有相关状态。

临时效果页将“暂停比赛”与“暂时禁止目击攻击”作为两个独立功能。前者冻结有效比赛时间，后者按真实时间运行，只限制指定范围的目击攻击。表单展示目标范围、持续时间、原因与来源，执行前预览。

效果列表显示起止时间、剩余时长、操作者、影响范围、是否仍有效。撤销一条效果后，若个人处罚或阶段限制仍存在，应明确显示仍然不能攻击的原因，不出现“全部恢复”的错误提示。

### 6.8 攻击复核与纠错

攻击复核列表可按文明、事件、结果和时间查找。详情仅向相应裁判展示请求标识、受理情况、当时阶段、规范化颜色组合、结算分类、错误次数变化、随机判罚记录、目标状态变化和关联通知。前端将后台分类翻译为完整中文，例如“提交的是已退役配置”“目标已被先提交的攻击击毁”。

有技术故障证据时进入纠错流程，填写原因，预览对航次、手环退役状态、母星、战绩、淘汰、排名、观战资格、通知和未来到期事件的影响，再执行统一业务操作。已经发生的情报传播保留在审计说明中，不在界面声称已收回别人看过的信息。

纠错后刷新涉及文明和事件，不删除原记录或重抽既定的第二次错误提交结果。恢复玩家资格时同步撤销赛中观战权限。纠错失败保留输入原因和服务器拒绝信息，允许重新核对。

### 6.9 手环处理与剩余配置

同色同款备用环替换仅记录替换及核对结果，保持当前配置。需要注销和换发时，进入“暂停比赛—查看旧配置—确认注销—领取新配置—确认新佩戴—恢复比赛”的管理流程；每一步以服务器结果推进。

新旧两臂配置均以色块显示，明确旧配置已退役和新配置是否生效。异常换码和正常重生共用本场350组永久发行记录；界面不提供复用历史配置或编辑颜色组的入口。

剩余配置页显示已发行数、尚可发行数及历史消耗来源。剩余20组、10组和0组时分别提醒总裁判；不足时显示具体任务，不擅自限制某个玩家的重生资格。

### 6.10 赛事事件与系统状态

赛事事件页按类别、时间、处理状态和文明筛选，详情联查业务结果、通知和操作记录。正在等待执行的计划只向有相应权限的裁判提供；投屏和观战始终只读已发生内容。

系统状态页展示最近成功调度、下一次唤醒、到期积压、最近错误和数据更新时间。总裁判可执行“重新安排调度”“结算到期事件”，预览范围后提交，结果必须包含实际处理情况。单纯页面可访问不等于事件正常运行。

备份与整场恢复放在高级运维说明和受限操作范围内，普通裁判页不提供一键重置比赛。涉及历史恢复时先暂停并查看影响，恢复后核查调度、发行历史、淘汰和通知；具体基础设施工具沿技术方案执行，不在本次前端规划中另建数据库管理器。

### 6.11 指令控制台

控制台提供命令搜索、参数提示、自动补全、目标选择说明、输入区域、预览结果、执行结果和历史。原有斜杠命令作为操作语法保留，说明、字段标题和错误信息使用规范中文。

| 功能组         | 必须覆盖的操作                                     |
| -------------- | -------------------------------------------------- |
| 查询           | 文明、航次、手环发行、事件、时钟、通知和历史       |
| 比赛控制       | 暂停与恢复、全场或指定文明的临时攻击限制           |
| 状态与资源修正 | 淘汰与恢复、母星、光粒、广播次数、航次与换码       |
| 事件处理       | 查询、补结算、取消、经授权的新事件、重播已公开内容 |
| 消息           | 全场公告、定向通知、公开统计、延迟发送             |
| 参数与效果     | 查看可调整参数、预览变化、建立或撤销临时效果       |
| 操作复核       | 操作原因、影响对象、前后变化、结果和相关审计       |

只读查询可直接执行。改变状态的命令先预览，显示明确目标、将变化的字段及后续影响；高影响操作要求总裁判权限与原因，最终按钮写“确认执行”。预览有状态版本，执行前服务端重新核验；版本变化时返回新的影响供重新确认。

随机目标命令在预览时说明候选范围和选择方式，不伪装成已经选定某人；执行结果记录真正选中的对象。延迟命令展示真实执行时间、状态和取消入口。成功结果可跳转到对应文明或事件；错误指出具体参数或状态，不整段展示内部堆栈。

查询、预览和执行调用同一套服务端管理能力，不在浏览器运行任意脚本或数据库命令。复杂条件表达式、命令宏和批量组合在基础控制台验收后建设，不用它们代替常用表单。地图及依赖场地几何的区域效果不纳入本网站。

### 6.12 结果、操作记录与活动设置

结果管理显示正式报告版本、结束原因、冠军和完整名次。提供正式战报导出与有权限的审计导出，明确各自文件内容。普通参赛者的复盘页与裁判内部审计不是同一份导出。

操作记录可按操作者、文明、动作、来源与时间检索；详情保留理由、前后状态、关联事件及结果。玩家复盘只得到与比赛结果有关的更正内容，不得到完整裁判会话或调试数据。

活动设置包含活动名称、简短说明、QQ群名称与号码、裁判联系方式、QQ群文件名称文本、消息模板预览、七色色值配置。这里不配置校园名称依赖、经纬度、路线、地图地址或地图上传项。QQ群材料名称可修改，页面只展示文字提示。

本期使用既有独立账号和服务端职责授权，裁判账号页展示当前权限。批量建立账号、发放口令、添加管理员等按既有赛前管理流程和受限指令处理，不为完整前端额外扩展公众账号系统。

## 8. 前端文案规则

### 8.1 统一表达

玩家、裁判、观战、大屏、QQ复制正文和导出报告中的可见文案均适用本节。技术文档中的路由、字段与命令语法可以保留必要的英文；不能把这些内部标识直接用作按钮或状态名称。

1. 使用完整、规范的汉语。动作按钮写出动作对象，例如“领取手环配置”“完成出航”“标记已发送”。
2. 不使用自创缩写、黑话、生造词或借用其他专业领域的术语描述简单动作。
3. 不使用间隔号连接身份或关键词；不使用带空格的斜杠串联标签。名称用自然语言、顿号、分行或完整句子组织。

6. 保留原玩法正式名称，如母星、飞船、光粒、歌者、技术爆炸、四维观察者；首次出现时用一句普通汉语解释。
7. 不添加防御性说明、泛化免责声明或自我保护式文案。真实的规则后果、操作确认和网络反馈直接表达。开发测试数据的说明放在开发文档或测试工具中，不加入正式页面文案。

## 9. 状态、时间与联网交互

### 9.1 状态来源与显示优先级

每次读取本人状态时统一取得阶段、飞船状态、母星状态、暂停原因、可用动作、资源、时间和当前记录版本。界面以服务端返回的动作集合控制功能，同时在读写接口重新验证；隐藏按钮不是权限机制。

页面主状态依次处理：比赛已结束；本人永久淘汰；本人重生流程；赛前准备；全场暂停或终局核验；阶段与个人行动限制；正常行动。这个顺序用于选择主要内容，各项独立状态仍然同时保留，例如已淘汰者在暂停期间的观战等待继续。

同一时刻多个条件变化时先使用服务器结算后的整体状态，不在前端依次模拟出中间生死结果。有效时间到65:00、90:00、98:00、120:00时立即取新状态，不能因本地旧按钮尚在就认可过期动作。

### 9.2 时间展示

| 时间用途               | 使用的时间                   | 暂停时行为                                   |
| ---------------------- | ---------------------------- | -------------------------------------------- |
| 发码与正式开赛倒计时   | 服务器确定的真实时间         | 按服务器计划显示，不套用开赛后的有效时间公式 |
| 阶段和比赛剩余时间     | 有效比赛时间                 | 冻结                                         |
| 重生截止               | 有效比赛时间                 | 冻结；全过程同一截止                         |
| 错误提交后的禁止攻击   | 真实时间                     | 继续                                         |
| 淘汰后180秒等待        | 真实时间                     | 继续                                         |
| 临时禁止攻击、定时消息 | 各管理效果明确声明的真实时间 | 按效果类型继续                               |
| 历史事件               | 生效比赛时间及相应真实时间   | 不随页面刷新改变                             |

比赛时间使用可超过59分钟的分秒表示，例如98:00。真实时间按活动配置的时区格式化；页面刷新取得服务器时间偏差，短期计数使用浏览器单调时钟估算，再定期校准。历史详情必要时分别显示“生效时间”和“记录时间”，不混为同一个时刻。

倒计时归零表示需要刷新资格，不自动宣布开赛、重生成功或观战授权。服务器尚未确认时显示正在更新，不把数字变为负数。

### 9.3 页面更新与应用切换

规划先采用可配置轮询，集中管理刷新频率。可见玩家页以约2秒刷新本人关键状态，公开事件以约5秒刷新；裁判待办约3秒，观战与大屏约5秒。具体间隔在联调和负载验收后确定，所有入口读取同一权威服务，不建立客户端比赛引擎。

切到QQ、高德地图或锁屏时降低后台请求频率；回到页面、恢复网络和页面获得焦点时立即刷新状态。加载中的旧响应若版本落后，不覆盖新状态；已离开页面的请求不把结果写进错误用户或错误场次。

重要变化以明确的页面状态和本人消息呈现，不依赖用户同意浏览器推送、后台声音、屏幕常亮或持续保持网页前台。声音和振动若后续增加，只作为用户主动启用的补充。

### 9.4 提交、重试与错误

每一次用户确认动作生成稳定请求编号，并保存与该动作绑定的提交摘要。重复点击只触发同一动作；超时后先读取结果或用同一请求编号与原始内容重试，不能为一次未确认的攻击、广播、光粒、发码或裁判操作创建新的结算。

需要补充通用本人操作结果查询能力，以便重新打开页面时只凭请求编号恢复结果。待确认操作仅持久化必要的请求标识和所属账号与场次标识，不存储会话令牌，不将登录口令、母星或整套秘密状态保存为普通离线缓存。精确恢复策略与服务端请求记录共同实现。结果暂时查不到时不能直接视为从未执行，先由服务端确定请求是否仍在处理。

| 页面情况             | 处理方式                                                   |
| -------------------- | ---------------------------------------------------------- |
| 首次加载             | 显示页面标题和加载状态，不显示虚假的零库存或零人数         |
| 已读取内容后短暂断线 | 保留内容和最近同步时间；重新连接后刷新                     |
| 明确离线             | 暂停战局提交，保留未提交表单；不把攻击排队等联网再自动执行 |
| 操作超时             | 显示正在确认结果，恢复原请求结果                           |
| 格式错误             | 在字段附近写清修改方法，保持原输入                         |
| 权限或阶段改变       | 刷新状态并进入当前可用流程，不继续提交旧操作               |
| 身份失效             | 清除秘密展示，重新登录后恢复当前状态                       |
| 过期审核或预览       | 显示最新数据，要求重新核对后确认                           |
| 系统返回失败         | 显示具体失败和可执行的重试入口，不先宣布成功               |
| 空列表               | 说明当前没有相应记录，不把空结果当作加载失败               |

浏览器后退恢复页面时重新校验权限，秘密数据不进入公共缓存。恢复参赛资格或退出账号后清除观战全局数据；其他标签页再次获得焦点或收到会话变化通知时也重新验证。

- [ ] 七种颜色使用统一版本化配置；修改任一色值后，玩家、裁判、观战、历史和大屏全部采用同一值。
- [ ] 黑、白、灰、黄、桔、天蓝、紫均显示为实际色块；显示名称的地方仍保留色块。白色在浅背景可辨，选中和不可用状态不改变原色含义。
- [ ] 现场按原验收要求以实际手环核对颜色，包括日光、树荫及夜间环境和典型色觉差异；记录辨认结果，不仅靠截图检查。
- [ ] 同色跨臂重复不可提交，合法的三类数量组合可提交，交换两臂及改变同臂顺序不改变含义。
- [ ] 本人现役配置在正常出航的个人页可见；被击毁后旧配置不再标为现役；其他在赛玩家无法读取。
- [ ] 六位口令保留前导零，接受任意合法六位字符串，不接入高德有效性判断，不额外要求目标编号。

### 13.3 玩法和时间

- [ ] 发码之前无法领取；发码之后尚未开赛不能攻击；全部穿戴就绪后统一开赛。
- [ ] 旧版母星登记不能通过审核；复制的口令和版本与服务器保存数据一致。
- [ ] 第一次错误提交禁止目击攻击5分钟；第二次由服务器确定永久淘汰或禁止15分钟；第三次永久淘汰。前端仅显示实际结果。
- [ ] 自己的码、已退役码、同请求重试、格式错误、阶段拒绝和真实并发例外不在前端自行增加错误次数。
- [ ] 一次攻击结果未知时不发起第二笔同内容新请求；刷新后可确认原结果。
- [ ] 重生步骤共用严格截止，成功出航才结束流程；母星毁灭、超时和65分钟能正确中断；原个人禁止攻击时间跨重生保留。
- [ ] 全场暂停冻结有效比赛和重生时间，个人处罚、180秒等待及相应临时效果按真实时间继续。
- [ ] 65分钟关闭广播、光粒、重生；90分钟隐藏目击；98分钟停止有效时钟；完成核验后才继续。
- [ ] 98分钟整批淘汰统一提交，普通恢复无法跳过核验；空名单、仅剩一人和无人存活均正确。
- [ ] 仅剩一个可重生文明时也能按服务器结果提前完赛；不只数当前出航者。
- [ ] 到120分钟关闭行动；所有提前完赛入口同样进入正确结果页。

### 13.4 权限、通知与复盘

- [ ] 在比赛中的玩家只能看到本人秘密和公开信息，没有全场战绩榜；广播提交结果不揭示真实归属。
- [ ] 淘汰未满180秒不能读取赛中全局详情；满180秒后可看到真实母星、手环、光粒发射者、技术爆炸获得者及已发生历史。
- [ ] 纠错恢复资格后立即关闭观战；无权限页面、缓存和旧响应不继续展示全局秘密。
- [ ] 观战和大屏不返回未来随机安排、原始抽签值、私人照片、凭证或管理指令；大屏仅使用裁判会话下的只读入口。
- [ ] 比赛结束后，幸存者和刚淘汰者都能直接查看本场完整复盘；比赛未结束不能凭修改路由提前进入。
- [ ] 名次、并列和全体淘汰无冠军结果与服务器一致；复盘与裁判内部审计范围分开。
- [ ] QQ复制、已发送及发送异常分别记录，复制失败不会记为已复制，通知延迟不重置比赛期限。
- [ ] 多裁判并发审核、通知处理和终局草稿不会用旧版本覆盖新状态。
- [ ] 指令预览不执行变更；真实执行重新核验权限和状态，重试不重复结算，临时限制撤销不解除其他限制。
