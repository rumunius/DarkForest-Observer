# 《黑暗森林：观察者效应》网站前端设计系统

版本：1.0。编写日期：2026-11-03。

## 2. 设计语言与参考图取舍

### 2.1 核心表达

用接近黑色的空间、少量清晰白线、留白和真实任务信息，形成安静的深空仪器感。科幻感来自几何秩序、准确的状态变化和颜色的空间移动，不依赖复杂HUD、霓虹或设定文案。视觉主次依次为：当前任务与结果、相关时间、可操作控件、辅助信息、环境星点。

默认一个页面只强调一件正在做的事。普通玩家看到可理解的比赛页面；不需要理解虚构仪表、内部编号或技术术语。

### 2.2 从参考图保留和舍弃什么

| 元素 | 采用方式 |
| --- | --- |
| 深黑背景、白色轮廓 | 保留高明度信息与低明度空间的对照，改为纯色底，不复制图中光晕、噪声和明暗纹理 |
| 倒角矩形 | 采用45度直线切角，固定切角方向与尺度；不是大圆角卡片 |
| 稀疏星点 | 少量小尺寸中性灰点，远离正文和色块，默认静止 |
| 手臂示意图 | 保留几何折线手部和前臂轮廓，作为真正承载颜色的功能图形 |
| 彩色手环 | 保留纯色条带；取消发光、体积高光、渐变和投影 |
| 十字准星、同心轨道、刻度、底部点列 | 无真实功能时全部删除；不把空白填成假雷达或假分页 |
| “左臂”“右臂” | 改为“一侧手臂”“另一侧手臂”，不能误导为解剖方向编码 |
| “状态、目击、消息、我的”导航 | 使用功能规划的“当前、行动、消息、我的” |
| 编号与昵称用间隔号串联 | 改为独立字段；合成一句用“C07（归零者）” |
| 四格统计、并排三个行动按钮 | 不照搬首页密度；统计放“我的”，行动在“行动”中按资格出现 |
| 顶部信封和菜单 | 有独立用途才出现；已有底部消息入口时不重复放同功能信封 |

### 2.3 硬性禁止项

1. 不使用照片、背景图、星空贴图、位图图标、图片形式的手臂或生成式插画。允许用内联SVG、路径及基础图形绘制手臂、图标、星点；不通过图片文件伪装整块界面。本文不交付这些图形的代码。
2. 不使用任何线性、径向、锥形或图像渐变；文字、背景、边框、星点、手环、遮罩都适用。
3. 不使用霓虹、外发光、磨砂玻璃、模糊光晕、纹理噪声、拟物金属、3D透视和装饰性投影。层级通过位置、明度和实线边界区分。
4. 除游戏手环色外，不使用高饱和强调色，不铺蓝、黄、红大色块；也不铺大型纯白宣传面板。大面积只有黑与深灰。
5. 不出现无功能的小文字、副标题、英文品牌角标、随机坐标、虚构在线状态、标语和假数据。标题、身份、时间、辅助操作说明有功能，正常保留。
6. 不用全屏闪白、镜头摇晃、扫描线、持续闪烁、飞船穿梭或爆炸演出表达结果。不让动画延迟事实出现。
7. 不把文明散点或星点画成地理地图、位置轨迹或可定位星图。网站仍无地图、定位及照片上传。

## 3. 色彩系统

### 3.1 中性色与语义色

下表为设计令牌名称及基准值。名称用于设计交接，不展示给玩家。色值集中维护，不让每个页面自行选近似灰。

| 令牌 | 色值 | 用途 |
| --- | --- | --- |
| canvas | #090B0E | 全站纯色背景 |
| surface | #111419 | 输入、必要容器、固定导航 |
| surface-raised | #191D23 | 对话框、按下反馈、当前操作区域 |
| text-primary | #F1F2F3 | 标题、正文、主要数字、主要图标 |
| text-secondary | #ADB3BC | 次级标签、真实辅助说明 |
| text-muted | #858D98 | 非关键元信息、占位提示；不承载操作后果 |
| line-quiet | #343B45 | 非交互分隔、低优先级结构线 |
| line-control | #77818E | 输入边界、可操作轮廓、手臂结构线 |
| line-strong | #D4D8DF | 主按钮、当前手臂、重要容器轮廓 |
| accent-info | #91ADCA | 信息链接、局部提示或焦点辅助 |
| accent-attention | #D0BE81 | 当前待办、暂停、需要核对的局部提示 |
| accent-danger | #CE9498 | 错误、危险操作、淘汰结果的局部提示 |

操作控件和正文不用低透明度整体淡化。强调色只进入一个短状态、图标、2px边线或短指示条，不能填满卡片、整行或页面。正常出航、母星尚存、成功完成默认使用白字与文字状态，不为所有正常状态添加黄色或绿色。

单屏非手环强调色的实色面积以不超过可见内容面积约3%为设计检查目标；同一任务一般只用一种强调色。多个真实警示需要同时出现时保留信息，用文字层级区分，不为了比例删掉警示。

### 3.2 手环色属于业务数据

七色身份和呈现值统一读取功能规划§7.1定义的版本化配置。设计基准图使用该文初始值：黑#1A1A1A、白#F5F5F5、灰#858585、黄#F4D12B、桔#F0802B、天蓝#56B7E6、紫#884CB5。它们仍是待实物校准的初始值，不是本设计系统重新冻结的物料标准。固定顺序为黑、白、灰、黄、桔、天蓝、紫。

- 手环是唯一允许明显饱和色填充的功能对象；同一例外适用于选色盘、手臂条带、列表中的配置色块和颜色设置预览。
- 不从黄色手环推导待办颜色，不从天蓝手环推导链接色。界面语义色与手环配置保持独立。
- 选中、悬停、拖动、只读、历史失效与提交锁定都保留原色，不叠加改变颜色的半透明层，不做去饱和处理。状态靠外侧标记和文字表达。
- 色块统一加1px可见中性边界，黑色不能融入背景，白色不能失去边缘。焦点框在色块外侧，与色块间隔2px。
- 可切换“显示颜色名称”；打开后名称与色块同在。默认以色块为主，读屏始终能读到中文色名。不能在实体手环图上加数字或纹样来创造额外编码。
- 色值变更覆盖全部展示空间与历史组件；不在某页单独美化颜色。现场按日光、树荫、夜间及典型色觉差异核对实物，详见技术方案§18、§20.5及功能规划§13.2。

### 3.3 可读性基准

本项目把普通文字与实际背景的对比度至少4.5:1、关键控件边界和焦点至少3:1作为交付验收目标。低对比星点和非交互分隔线不承担信息。必须在实际组合上测量，不把令牌表视为已通过测试。手环色不得为达成文字对比而改色；必要的文字放色块外，以中性高对比文字表达。

## 4. 字体、数字与文字层级

### 4.1 字体方向

中文采用清楚、偏几何的无衬线黑体。首选思源黑体或Noto Sans SC的常规与中粗字重；上线前确认字体文件与授权，不能因字体加载失败导致正文隐藏。无字体资源时使用设备中文无衬线回退，不临时引入装饰性科幻字体。拉丁字母沿同一字体体系；倒计时、文明编号、六位口令采用等宽数字特性，确无支持时回退到可清楚区分0与O、1与I的等宽字体。

最多两套字族、三个常用字重：400、500、600；不铺超细字、不用倾斜字表现速度，不把整段中文拉大字距。

| 用途 | 手机字号与行高 | 字重与说明 |
| --- | --- | --- |
| 页面标题 | 24px / 32px | 600，一页一个主标题 |
| 分区标题 | 18px / 26px | 600，只为真实内容分组 |
| 主要正文、按钮 | 16px / 24px | 正文400，按钮500或600 |
| 次级标签 | 14px / 22px | 400，不用于压缩关键后果 |
| 时间等元信息 | 13px / 20px | 400，避免大量使用 |
| 关键倒计时 | 40px / 48px | 500，窄屏可32px / 40px |
| 六位口令 | 24px / 32px | 等宽数字，保持一个整体 |
| 文明编号 | 18px / 26px | 500，昵称独立一行或字段 |

上述值为默认字号基准，随用户字体放大而重排，不锁死页面高度。裁判桌面正文可14px / 22px，但关键操作仍16px；大屏正文建议至少24px，标题32px，主时间56px起，最终按实际观看距离验收。

### 4.2 文案约束

功能规划§8继续生效。禁止用装饰英文补齐角落，也不为页面标题加一句无任务价值的诗句。“DARK FOREST”“当你凝视深空，深空也在凝视你。”不能作为页面角标或副标题。活动全名可以作为进入页的真实标题，登录后的任务页不重复堆品牌名。

按钮写“确认攻击”“领取手环配置”“完成出航”等具体动作。不要照抄参考图的“失配次数”“击毁数”，采用“提交错误目击码的次数”“已击毁的不同文明数”。较长标签正常换行，不能为了对齐删掉决定含义的字。

## 5. 几何、线条与空间

### 5.1 倒角规则

主容器和按钮使用45度切角：左上与右下各切一个角，其他角保持直角。切角沿水平与垂直方向等距，不用圆弧冒充切角。组件高度小于44px时不强行加切角。

| 对象 | 切角尺寸 | 边线 |
| --- | --- | --- |
| 普通按钮、输入框 | 6px | 1px实线 |
| 主要任务容器、对话框 | 10px | 1px实线 |
| 宽屏大型摘要容器 | 12px | 1px实线 |
| 键盘焦点、当前手臂外框 | 跟随对象形状 | 2px，外留2px间隔 |

只给需要识别边界的交互区或任务区画框。正文、每行统计、每个分组不都套卡片；不叠三层轮廓，不加四角支架。标题下可有一条功能分隔线，但不向空白延伸成复杂线路。

### 5.2 间距与尺寸

间距采用4、8、12、16、24、32、48、64px序列。手机左右边距20px，360px及更窄用16px；组件内部16px，区块间24—32px，任务内关联元素8—12px。桌面内容边距32px，分栏间32px。

普通按钮最低48px高；图标按钮和色块点击区至少44×44px；相邻点击区间隔至少8px。手环的可见条带可以小于点击区，但各自点击区不能重叠。

空旷感来自区块之间和手臂周围的空间，不能靠减少正文可读性、把操作赶到屏外或放大无用空白实现。数据密集的后台保留清楚间距，不照搬玩家手臂页的大留白。

### 5.3 星空规则

仅进入页、当前页的空白区域、独立手环页和大屏允许出现环境星点。目击操作区、列表、表单、弹窗、裁判工作台默认不铺星点。

每个手机可见视口最多8—14个星点，宽屏最多24个；直径1—2px，单点最大3px。用两档低明度中性灰，位置固定、不成规则网格、不随数据刷新随机重排。星点离文字和控件至少16px，不能穿过手环色块或看起来像未读红点。它们不承载数据、不响应指针、不进入读屏顺序。默认无闪烁、无漂移、无视差；气氛由静态空间承担。

### 5.4 图标规则

图标采用24×24px设计网格、1.5px统一描边，导航可以放大到24—28px；线端和折角保持干净，避免锐利长刺。使用同一套几何线性图标，不混合实心、粗线、手绘与拟物样式。圆形只用于语义明确的图标或小状态点，不把全部按钮改成胶囊。

“当前”可用简洁状态面板，“行动”用目击眼形，“消息”用信封，“我的”用人物轮廓；图标始终配导航文字。目击、广播、光粒、母星可分别采用眼形、信号线、简化准星、行星轮廓，但只在对应功能存在时使用，不复制成背景装饰。

图标按钮必须有可读名称；仅靠形状容易混淆的操作保留可见文字。未读标记使用4—6px小点或真实计数，不持续闪动，不以红点表示不存在的消息。

## 6. 布局与页面骨架

### 6.1 移动端

主要验证360×640、390×844、430×932，补充320px宽及200%文字放大。页面按“标题或返回—关键状态—主要任务—必要确认—导航”组织，首屏只保留当前任务必需项。

玩家导航固定为“当前、行动、消息、我的”，每项用一个线性图标和文字。选中项以白字、2px短下划线和程序化选中状态表达，不能只靠黄色。导航高度64px加底部安全区；页面底部预留对应空间，不遮挡最后一项内容。二级任务可用返回栏降低视觉重复，但四个主入口仍须直接可达。

有键盘时任务区域允许自然滚动，输入和提交保持可见；不要把输入框、提交栏和导航叠在键盘顶上。若吸底确认栏在矮屏或放大文字时遮挡内容，将其放回文档流；保留导航可达与浏览器返回。

390px宽的目击页面优先显示完整双臂、色盘、后果和确认按钮；360×640及更矮视口允许滚动。不能为了宣称首屏完成而把处罚说明缩成小字。

### 6.2 宽屏与后台

以可用内容宽度而非设备名称决定布局。小于768px以单列为主；768—1199px可在实际容得下时并列摘要与任务；1200px起允许裁判列表与详情并列。

玩家单任务内容最大宽560px，带侧摘要的双栏总宽不超过960px；两臂图示不随屏幕无限放大。裁判桌面采用约216px侧导航、可伸缩列表和详情；正文总工作区建议上限1600px。表格只在必要时局部横向滚动，整页不横向溢出；手机改列表到详情的前后页。

大屏独立设计16:9布局，按实际展示距离增大文字；内容超出时分页，不挤满24个微小文明卡片。允许可关闭的自动轮播，切换规则见§10。

### 6.3 分层

从底到顶为背景与星点、内容、固定导航与确认栏、弹层、拖动中的手环、紧急状态提示。层级是概念顺序，后续集中定义。模态弹层打开后停止底层拖动；权限撤销时秘密内容立即移除，不能通过淡出留存。弹层遮罩为均匀纯黑透明层，不使用模糊或渐变。

### 6.4 渐进式披露

全站按[功能规划§3](网站前端页面与功能规划.md)的披露总则与玩家状态矩阵组织界面。用户于2026-11-03明确要求仅展示当前游戏状态能用到的UI；本节据此细化原设计中的展示条件，不改变游戏规则。以下规则优先于本文组件表中未加条件的功能列举。

**分步式：** 母星登记、首航、重生每次只展示当前步骤的表单、说明及动作。步骤完成以服务器确认推进；已完成项收为简短只读摘要，需要查看时主动展开。未来步骤不渲染输入、配置图、按钮或灰色占位；可以用一句话说明下一步，但不展示整套未来操作。服务器没有单独状态的现场动作，以当前步骤的一组说明承载，不新造“已到达母星”等业务确认。

**条件式：** 操作规则、历史航次、详细战绩、筛选条件等由明确文字入口展开或进入详情，默认保持摘要。展开控件写“查看目击规则”“查看历史航次”等具体名称，关闭后焦点回入口。不得把当前后果、期限、处罚和必做步骤放进折叠区；条件式展开也不能显示当前无资格操作或越权数据。

**情境式：** 入口、卡片、输入和确认区随服务端允许动作及当前草稿显示。无资格时移除整组操作，不保留灰色发射按钮、无库存卡、未来领码框或无意义占位。被击毁尚未完成重生时隐藏广播、光粒和目击操作；正常出航时隐藏领码、就绪及重生操作。本人现役配置和已发生消息是可读记录，保留在主动查看的详情中，不能附带不适用的操作。

四项主导航保持稳定，属于定位和查看当前信息的通路；没有合法行动时，“行动”只说明当前状态并指向当前任务，不列出所有不能使用的功能。规则、联系裁判、账号与有权查看的历史继续可达。裁判端同样按职责、所选对象和当前流程显示操作，复杂参数按需展开；只读大屏不出现管理控件。

视觉层的隐藏必须同时移除点击、键盘和读屏入口。返回、刷新、切回QQ、消息跳转、资源用尽、暂停及状态变化都重新核验；不因用户曾展开或访问过而继续保留旧操作。正常切换可短暂过渡；权限撤销或资格失效时立即撤下操作和相关秘密，不等待动画结束。

要区分三种情况：当前没有此业务资格时隐藏整组操作；当前合法表单未填完时保留输入和完成说明，最终提交动作在有效后才出现；请求已提交但结果未知时保留原请求只读摘要与确认结果进度，避免重复操作。断线保留合法草稿和联网说明，暂停提交，不把临时网络问题当作玩家状态改变。

## 7. 手臂与手环组件

### 7.1 图形构造

以少量直线段形成伸直手掌、手指和前臂；轮廓1.5—2px、白或浅灰，无肤色、指甲、关节纹理与写实阴影。两只手的视觉重量一致，图形正立，前臂末端自然裁切。手掌只帮助识别“手臂”，腕部条带才是信息焦点。

条带用横向等宽纯色几何带覆盖腕部，必要时用小幅直线切角表示绕腕关系，不画亮暗侧面。各色的高度与宽度一致，不能用粗细区分编码。同一臂最多展示三条，条带之间留足间距；输入组件每条仍有独立44px触控带。

两臂外侧或上方显示“一侧手臂”“另一侧手臂”和实际条数。不要画三个固定编号的插槽，不写“第一环”“最外侧”，不让空槽暗示每臂都要戴三条。空臂直接显示“尚未选择”。

展示顺序按固定颜色顺序稳定排列；新颜色落位后可让其他条带短距离让位，但用户无需按这个顺序佩戴。同组没有拖动排序功能。旁边保留一次必要说明：“同侧顺序不限，两侧可以交换。”

### 7.2 展示模式必须可区分

| 模式 | 标题与交互 |
| --- | --- |
| 本人现役 | “本航次手环”，只读，不出现候选色盘或移除提示 |
| 首航与重生待佩戴 | “需要佩戴的手环”，只读配置，可整体交换示意，配服务器允许的确认按钮 |
| 目击输入 | “目击攻击”，两臂可选择、手环可移入移出，显示候选色盘 |
| 历史配置 | 显示航次、生效或失效时间及“已失效”；保留原色，不靠变灰说明退役 |
| 观战与复盘 | 只读，所在文明与记录时间清楚，不出现攻击或拖动能力 |

完整手掌图仅用于需要理解佩戴或输入的页面。列表内用两组小色块和条数表达，不在每行重复手臂插画。

## 8. 目击输入：色块就是可移动的手环

### 8.1 固定结构

仅在当前有目击资格时显示本输入页。从上到下：页面标题与返回、两臂输入图、共享七色盘、按输入情境出现的工具、当前错误次数及下一次错误提交后果、合法组合形成后出现的“确认攻击”。至少选择一色后才显示“清空选择”；两侧均非空时才显示“交换两侧”。正式广播和光粒只在各自具备资格时作为行动页独立入口，不挤进目击确认区。

双臂各有可点击标题与图示区域，当前输入侧使用中性亮边框和“正在选择”文字，不改变手臂中任何颜色。两臂是最终输入结果本体，不再复制一套彩色结果条增加视觉负担。

共享色盘按七色固定顺序采用四列加三列的两行网格；空间足够时可以七列，但每格触控尺寸不得减小。色块可见面建议32×20px，外层至少44×44px。固定保留七个位置，已移走的颜色留下没有色块、图标和文字的空位；空位不响应点击、不进入键盘焦点。色盘不因选中而紧密重排，避免下一次点击落到别的颜色。

空位仅维持网格位置，不画灰色禁用色块、划线副本、“已使用”小标签或另一枚同色手环。每种颜色在稳定画面中只有一个实体：要么在色盘，要么在一只手臂上。

### 8.2 点选主路径

1. 初始两臂为空且未指定输入侧，显示“先选一侧手臂，再选颜色”。此时点颜色只提示选择手臂，不默认猜一侧，也不把全部色盘置灰。
2. 点击某个手臂标题或空白图示，设为当前输入侧；焦点框与“正在选择”标记同步切换。
3. 点击色盘中的一种颜色，该颜色立即归入当前侧，并从原格移出，动画落到对应腕部条带位置。动画开始即更新本地选择、计数和可提交性，不等动画结束再登记。
4. 当前侧保持不变，不因已选两条或达到某种组合自动切换到另一侧。用户自己点另一只手臂再继续。
5. 点击已在手臂上的手环，移除它并退回原色盘位置；无论当前输入侧是哪边，都移除实际被点的那一条。当前输入侧不因此切换。需要改变输入侧时点击标题或图示空白，避免与移除动作混淆。
6. 不使用拖放时，跨臂移动的等价路径是“点击原手环退回—选择另一侧—点击颜色”。不增加隐藏手势或长按菜单。
7. “清空选择”一次退回所有已选色，恢复未指定输入侧，不弹确认框。“交换两侧”整体交换集合，只改变展示；当前输入侧仍是屏幕上原选中的那个输入区。两个输入区的名称不互换。
8. 修改草稿不会发起网络攻击。只有点击“确认攻击”才提交一次最终请求。

### 8.3 拖放快捷路径

拖放包括鼠标、触控笔和手机触摸；不依赖浏览器仅对鼠标有效的原生拖放行为。接手工程师应为指针取消、页面滚动与应用切换提供统一恢复。

| 起点与落点 | 结果 |
| --- | --- |
| 色盘 → 任一手臂 | 加入落点手臂，落点成为当前输入侧；不必预先点击该侧 |
| 手臂 → 另一手臂 | 一次性转移该颜色，保持全局只有一枚；落点成为当前输入侧 |
| 手臂 → 色盘范围 | 退回该颜色固定原位；不要求精确投进某个小格 |
| 手臂 → 本手臂 | 保持原集合与稳定顺序，不产生同臂排序 |
| 任意 → 区域外、非法容量目标 | 回到拖动前位置，保留原集合；非法目标同时给出短原因 |

鼠标移动超过6px后进入拖动；手机在色块上按住约180ms且移动未超过8px时提起，提起前的明显纵向移动继续正常滚动。提起后再移动进入拖放；短按并松开走点选路径。触摸在页面其他地方起手始终能滚动，不把整张手臂图变成阻止滑动的大拖拽面。上述阈值是初始调校值，按真机试用统一调整。

提起后只有一个完整原色实体跟随指针，原位置暂留无色空位；不要保留原色副本再飞一个半透明副本。触摸拖动实体可上移约20px避开手指。可接受目标用2px亮轮廓，不铺大色块；非法目标不吸附、不挤走已有手环。

放下后才提交本地集合变化。悬停不同手臂不提前改变归属。拖动期间暂停其他颜色编辑及最终提交；有效落点以最新草稿校验。取消拖动、Esc、指针丢失、切换应用、旋转或尺寸改变时恢复拖动前草稿，不创建副本、不丢颜色。状态失效或服务端限制到来时立即终止拖动，再按最新业务状态处理。

### 8.4 数量、非法组合与编辑中间态

编辑中允许空臂、两条与零条、一条与一条等未完成中间态。单臂最多三条、总数最多四条；超过时拒绝本次加入或转移，已选内容保持原样，并提示“每侧最多选择3条”或“最多选择4条手环”。被拒颜色留在色盘或返回拖动起点，不能变成禁用候选色。

只有两条与一条、两条与两条、三条与一条及其交换形式可提交。编辑阶段的格式问题在本地提示，不提交攻击、不增加错误次数，不自动补色或删色。跨臂移动按移动后的整体集合判断，不先复制再去重。

未形成合法组合时不显示“确认攻击”，在确认区域显示“请选完两侧手臂的颜色”或准确的数量说明，不留禁用按钮或按钮形空框。合法后在同一区域出现最终按钮，不自动提交、不抢焦点；读屏只播报一次可以确认。后续删色导致不合法时撤下按钮，焦点若在其上则移到输入区标题。数量合法也不等于真实命中，页面不得猜目标或推荐配置。

### 8.5 最终确认、请求与状态变化

确认区始终呈现服务器返回的当前错误次数和下一次错误提交后果。文字允许多行，不能缩进悬浮提示、仅用红色感叹号或放入需额外展开的说明。后果按功能规划§4.5原文呈现，第二次错误提交的两种概率都必须完整出现。

点击“确认攻击”后立即锁定当前草稿及请求，取消未完成的视觉位移并让手环落在最终位置。输入区保持原色、保留结果摘要；整个输入区标识“正在确认攻击结果”，不能把候选色变成一排禁用彩色按钮。提交锁定不属于“选中色留在色盘”的旧模式。

请求结果不明时继续锁定，查询原结果或以同一请求恢复；刷新、切回QQ后不产生新攻击。得到明确的已完成攻击结果后清除输入，返回空选择，等待玩家再次现场观察。格式错误保留输入，限速按服务器时间恢复，资格或阶段拒绝转到相应状态；不把这些拒绝误判为已经结算的一次攻击。

主导航短暂切换可在当前会话内保留未提交草稿；回到页面时重新校验状态。刷新不要求保留秘密颜色草稿，未确认请求按功能规划§9.4恢复；不把完整颜色与母星秘密写入普通离线缓存。已失去操作资格时不保留可继续提交的旧表单。

### 8.6 键盘与读屏

手臂选择、色块、已选手环、清空、交换与确认都能通过键盘操作。空色盘格不占焦点；颜色移走后焦点落到对应已选手环，退回后落到原色盘按钮，不能掉到页面顶端。

读屏名称包含颜色、所属区域与动作，例如“黄色，一侧手臂，点击移除”。操作后一次播报“黄色已移到一侧手臂，共2条”；拖动逐帧不播报。无拖放时完整点选路径可完成所有配置。两臂图形有语义组名，内部手指轮廓不单独进入读屏。

## 9. 共用组件状态

| 组件 | 默认与活动状态 | 异常和细节 |
| --- | --- | --- |
| 主按钮 | 深底、浅色1px倒角边框、16px动作文字；一任务一个主要按钮 | 悬停略提升中性表面明度，按下最多缩至98%；危险动作仅红色文字或边线 |
| 次按钮与文字入口 | 普通中性边线或明确文字链接；不与主按钮同等抢眼 | 不依赖悬停才出现，不做纯装饰箭头 |
| 普通输入框 | 48px起，倒角细边；标签常驻外侧 | 聚焦外框清晰，错误文字紧邻；错误不清空原输入 |
| 六位口令 | 一个整体文本框，数字键盘，可粘贴，保留前导零 | 不拆六个小格、不格式化成数值；复制反馈不改变口令 |
| 状态摘要 | 阶段、具体时间标签、当前状态；最多一个关键倒计时被放大 | “比赛剩余时间”和“距离重生截止”等不能统称“剩余时间” |
| 统计 | 标签加值，必要时一条分隔线 | 空数据不先写0；不同文明数用准确名称，不借图标省掉含义 |
| 标签切换 | 文字与短下划线；允许换行或另页筛选 | 不做无限横向标签带，不把筛选结果伪装成正式排名 |
| 消息与事件行 | 类型、正文摘要、发生时间、必要来源 | 新消息提示不推走正在读的历史；未读用实心小点和账号阅读状态 |
| 复制 | 明确按钮，成功后局部显示“已复制” | 剪贴板失败提供可选择正文，不假报成功；QQ发送状态另记 |
| 对话框 | 一个标题、对象、后果与明确确认动作 | 只在流程需要时使用；焦点进入并受约束，关闭后归位；不叠弹窗 |
| 错误与连接提示 | 局部文字加小图标，必要时提供恢复按钮 | 重要状态持续可见；会话失效清除秘密内容，断线标最近同步时间 |
| 加载与空状态 | 静态框架配“正在加载”；空状态用一句事实说明 | 无渐变骨架屏、假百分比、虚构事件、无意义插画或额外标语 |

持续重要状态不只用自动消失的短提示。轻量复制成功提示可在2.4秒后退场；提交失败、待确认、处罚、被击毁及淘汰等必须有可返回阅读的明确状态。

## 10. 动效语言

### 10.1 目的与曲线

动效只解释用户刚做的操作、空间归属或真实状态变化。整体气质是快速起步、柔和停稳，避免匀速机械平移，也不做弹跳玩具感。“非线性”主要通过速度缓动表达，不要求每条轨迹画弧或弹簧。

| 动效令牌 | 时长基准 | 缓动控制点或节奏 | 用途 |
| --- | --- | --- | --- |
| press | 80—100ms | cubic-bezier(0.2, 0, 0, 1) | 按下反馈与复位 |
| feedback | 120—160ms | cubic-bezier(0.2, 0, 0, 1) | 焦点、选臂边界、局部状态 |
| enter | 200—240ms | cubic-bezier(0.16, 1, 0.3, 1) | 页面内容短距离进入、弹层出现 |
| exit | 140—180ms | cubic-bezier(0.4, 0, 1, 1) | 普通内容退出 |
| transfer | 280—360ms | cubic-bezier(0.22, 1, 0.36, 1) | 色盘与腕部之间的手环移动 |
| settle | 160—220ms | cubic-bezier(0.2, 0.8, 0.2, 1) | 拖动放下、非法落点返回、其他条带让位 |

同一语义在各页使用同一令牌。普通动画不超过400ms；不通过拉长动画掩盖请求耗时。不增加持续待机动画、装饰倒数或随机闪光。

### 10.2 手环转移

点击色块后，唯一可见实体从原格中心移动到实际手环位置，尺寸从候选小条带连续变化到腕部宽度，颜色与不透明度保持一致。可采用直线路径加缓动；需要避开标题时允许轻微弧线，偏离直线路径不超过约24px。没有尾迹、粒子、模糊或额外副本。

退回走反向空间路径，清空时所有颜色同时回原位，不逐条排队等待。“交换两侧”将两组条带作为整体平移并落位，不镜像翻转文字，不让两个色组相互绕圈。

点选动画不锁住下一次点选；快速连续操作以最新草稿为准，动画可中断并从当前视觉位置续接，不能排成长队。用户点击仍在移动的已选颜色时能撤回该色，不产生第二枚。无法稳定计算位置、视口尺寸变化或页面失焦时直接落到最新正确状态。

拖动时跟手，不额外施加缓动造成拖尾；缓动只作用于提起反馈和松手后的落位。拖放命中和点击命中以真实控件区域为准，不让展示层遮住目标。

### 10.3 页面与数据

主导航切换使用最多8px位移与160—220ms淡入；一级入口地位相等，不轮流从左右飞入。二级进入与返回可用12px方向位移，读屏焦点和浏览器历史同步。首次内容出现最多分两批，间隔40ms，总时长不超过320ms；当前任务与按钮不等待长串瀑布式登场。

数字直接更新，倒计时不滚轮翻页、不每秒缩放。轮询返回不重播进入动画。新事件只提示入口，不强制滚屏；重要生死与权限变化先立即显示准确文字，允许外框在随后120ms内完成状态变化。

大屏自动轮播默认关闭，由展示操作者开启并设置停留时间，建议初始12秒；切换不超过240ms，每页给足阅读时间。普通手机列表不轮播。

### 10.4 减少动态效果与性能边界

尊重系统减少动态效果偏好，并在账号显示偏好中提供对应开关。开启后取消空间飞行、缩放、页面位移和自动轮播，手环直接在两处完成归属切换；可保留不超过100ms的中性轮廓变化，颜色本身不淡入淡出。功能、计数、焦点与结果完全一致。

动效以稳定60帧为实施目标，不作为本次已实测结论。后台页面、隐藏标签页与切到QQ时停止非必要动画；恢复后直接对齐最新状态，不补播离线期间的演出。低性能设备或位置计算失败可即时落位，不能丢输入。

## 11. 全站页面应用

统一令牌、控件与状态规则覆盖功能规划§3的全部路由。下表给出页面族的视觉编排，具体字段、可见性与步骤按功能规划执行。

| 页面族 | 视觉编排与主要任务 |
| --- | --- |
| 进入比赛、玩家登录、裁判登录 | 进入页可有稀疏星点和活动标题；登录页收敛为一个表单、一个主按钮及必要规则入口，无海报和标语 |
| 昵称与母星登记 | 常驻字段标签、确认内容、保存或审核状态；QQ材料步骤用文本，不嵌地图与照片 |

| 首航与重生 | 一次突出当前步骤，已完成步骤可回看；佩戴步骤用双臂图；全过程相关期限明确，步骤动画不替代服务器确认 |
| 目击攻击 | 按§8共享色盘与可移动手环；手臂是操作中心，处罚及确认是第二视觉重点 |

| 被击毁、淘汰等待、转场与核验 | 一项明确状态、一组必要线下步骤、真实倒计时或等待说明；保持安静，不做失败惩罚演出 |
| 消息、情报、个人战绩 | 清楚列表与详情，时间对齐；六位情报可复制；历史按发生时信息展示，不制造实时秘密数据 |
| 我的、本人手环、账号 | 身份、状态、配置入口、战绩、规则与账号分区；完整手臂图进入手环详情，退出比赛单独确认 |
| 联系裁判、异常申报、规则 | 功能文字与可选择复制正文；规则有目录及正常滚动，不拆成强制翻页卡片 |
| 宇宙观测 | “战况、文明、事件、我的”固定入口；以数字摘要、文明列表和时间线表现全局，不画无功能星图 |
| 观战文明详情 | 只读双臂、母星与资源摘要，下方航次和事件；明确当前与历史，不出现可拖动光标 |
| 观战大屏 | 阶段和时间为视觉锚点，当前页聚焦概况、文明、事件或结果之一；独立只读视图，空白中可有少量星点 |
| 比赛结果、完整战报、文明复盘 | 真实冠军情况与正式名次为主；无冠军不造领奖台；事件与航次正常滚动，无彩带、奖杯图片或庆祝闪烁 |
| 裁判工作台、审核、开赛准备、通知 | 简洁工作列表、数量入口、详情与明确动作；状态文字优先，背景无星点；复制与已发送分开 |
| 文明管理、终局执裁、比赛时间、临时效果 | 列表和详情联动，当前值与拟变更值分栏；批量核验草稿明确，不能视觉上提前宣布淘汰 |

## 12. 时间、隐私与状态的视觉约束

1. 比赛时间、重生时间按有效比赛时间呈现；个人禁止目击、淘汰后观战等待按真实时间呈现。暂停时只冻结应冻结的时间。数字可以超过59分钟，不能把98:00改成钟表含义不明的格式。来源：功能规划§9.2。
2. 全场暂停作为当前阶段上的状态，不能把“暂停”设计成新比赛阶段；98分钟资格核验要明确等待裁判，不用自动完成进度条。
3. 倒计时归零显示更新中并刷新资格，不能在动画结束时自行开放操作、宣布出航成功或展示观战秘密。
4. 攻击未产生击毁时，普通玩家看不到历史码、自码、未发行等内部分类，不能用不同颜色、图标、动画或隐藏提示间接泄漏。
5. 授权边界适用于文字、图形、拖动副本、动画缓存与无障碍名称。退出账号、观战权限撤销时立即清除秘密；不等待退出动效。
6. 广播、光粒等结果按实际服务器事件展示；不画预计歌者清理进度、秘密抽签转盘、真假母星命中预览。
7. 断线可保留已授权且最近读取的内容并标时间，不能显示虚假的实时同步状态；会话失效与权限撤销必须清除相应秘密内容。

## 13. 设计交接与后续变更

### 13.1 后续设计师应提供的可审查材料

- 一张令牌页：色彩、字体、间距、切角、描边和动效基准；手环配置与界面语义色分开。
- 一套组件状态：默认、悬停、按下、键盘焦点、只读、不可操作、加载、错误；手环额外包含移入、退回、拖动、取消和提交锁定。
- 关键页面设计：进入与登录、正常当前页、目击空态及合法态、佩戴、重生、淘汰、消息、裁判列表详情、观战、大屏和赛后复盘。
- 目击交互分镜：先选臂、颜色起点、移动中、落位、跨臂拖动、无效放下、清空、交换、快速连点、减少动态效果。标出时长、轨迹与焦点归属。
- 响应式说明：手机、窄屏、字体放大、键盘展开、桌面、外接大屏；每项说明哪些内容重排，不能只交一张390px截图。
- 文案与数据映射：所有示例数字仅为设计稿示例，正式页面从对应权威来源读取；示例说明留在设计材料中，不进入正式界面。

本次不生成上述页面稿、代码或可点击原型；它们是后续执行时的交付要求。

### 13.2 保持一致性的变更规则

新增页面先选已有页面骨架与组件。不要为一个按钮新增相近颜色、为一张卡片新增不同切角、为每个页面发明不同动画。确需新令牌时记录用途与影响，并更新本文。

纯视觉调校可以在本系统范围内迭代；改变颜色身份、两臂含义、提交时机、处罚展示、信息权限、导航功能或游戏流程时，先核对功能规划及导航所列原文，出现冲突及时询问用户。授权后的规则调整继续通过补充文档记录，并更新文档入口，不能直接修改两份受保护核心文档。
