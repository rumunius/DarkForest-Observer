# 后端接口与运行说明

## 架构与数据

浏览器通过同源 `/api` 请求进入Pages Functions，再调用 `MATCH_DO.getByName('match:' + MATCH_ID)`。每场SQLite保存账号、会话、正式名单、比赛状态、航次、永久码本、攻击、情报、事件、通知、审计与结果。

当前业务schema版本为6，由 `storage/schema.ts` 管理，升级在同步事务中执行。本地状态位于 `.wrangler/state/`；Workers测试使用独立临时存储。已有本地场次重启后保留。2026-11-05新增的人工淘汰恢复、事件计划/诊断、故障通道及通知审计见[审计修复说明](审计修复说明_2026-11-05.md)，其中列出新增接口和迁移边界。

正式名单是人数的来源：`N = len(正式名单)`。预注册账号可多于正式玩家。总裁判在开赛准备或活动设置中选择正式账号。锁定T0时核验每名正式玩家的准备状态，锁定T1时按最终正式人数计算技术爆炸次数并保存秘密时刻。

## 本地启动

```powershell
cd E:\forest
npm ci
node scripts/local_setup.mjs --players 24
npm run dev
```

另一个终端执行 `npm run local:init`。初始化工具首次建立场次，账号文件为 `.private/local-rehearsal/accounts.json`，密钥文件为 `apps/match-worker/.dev.vars`。账号文件已存在时，生成工具保留原文件。数据库中的初始化标记阻止覆盖已有场次。

三个进程默认监听本机回环地址。手机联调时，将Vite启动改用 `npm run dev:lan --workspace @darkforest/web`，并在Pages本地 `.dev.vars` 的 `TRUSTED_ORIGINS` 中填写手机访问的完整来源地址。内部Worker与Pages继续监听回环地址，由Vite代理连接。

## 登录与安全

每个玩家及裁判账号使用独立的43位随机口令，字符为大小写字母、数字、短横线和下划线。服务器保存SHA-256摘要。会话令牌也只保存摘要，有效期12小时；Cookie为HttpOnly和SameSite=Strict，preview额外使用Secure。本地HTTP使用独立Cookie名称。

写请求检查可信Origin、JSON类型、正文大小及CSRF。登录接口以口令换取会话，其他写操作使用会话Cookie和CSRF头。裁判每项操作按职责权限检查。通讯裁判、事件裁判和总裁判分别使用J02、J03、J01账号。

## 时钟、配置与结果恢复

T0/T1采用UTC；阶段、重生和宇宙事件采用有效比赛时间；个人禁止攻击及观战等待采用UTC。入口与Alarm共享到期结算。事件依生效时刻、优先级和稳定ID排序。98分钟事件在原计划UTC打开资格核验暂停，时钟固定在98:00；总裁判完成整批核验后恢复。

赛前参数范围及默认值见[赛前参数与正式名单补充](赛前参数与正式名单补充_2026-11-04.md)。锁定T0后，参数写接口返回PARAMETERS_LOCKED。规则页、攻击确认与观战倒计时读取本场参数。

网络中断后，前端先查询原request_id；没有结果时调用resolve。取消结论与迟到请求的最终提交在同一DO中互斥，前端取得确定结论后释放操作状态。

## 裁判指令与更正

当前控制台支持查询文明状态、比赛时钟、手环容量、已发生事件；暂停恢复；按UTC暂时禁止目击；修改光粒库存；恢复资格；异常换码；群公告和指定玩家私信。具体语法由 `services/commands.ts` 中的注册规则校验。

攻击更正选择具体攻击记录。总裁判先暂停比赛，预览后执行。更正恢复原错误次数及限制时间，撤销相应有效淘汰或击毁战绩。需要恢复出航时，原配置保留在永久历史中，发放新配置，由裁判核对穿戴后激活。已有后续航次、其他淘汰原因或后续攻击时，服务端返回相应关联记录冲突，交给总裁判逐项复核。

## 备份与恢复

总裁判在赛前、暂停期间或完赛后导出备份。文件包含schema、场次、版本、生成时间、PITR书签及AES-GCM密文，AAD绑定场次与生成时间。解密使用对应环境的CODE_ENCRYPTION_KEY。密钥及原始登录口令分开发放和保管。

正式战报导出包含名次、战绩及公开事件；审计导出读取完整操作记录。完整复盘仍通过受权限保护的页面提供。

需要恢复的时间点必须先保存checkpoint。恢复入口使用独立BOOTSTRAP_SECRET，不使用玩家或裁判会话。按以下次序执行，文件存入被Git忽略的私有目录：

```powershell
node scripts/recovery.mjs prepare --origin https://dev.darkforest-pages-dev.pages.dev --secret-file .private/preview-rehearsal/secrets.json --input .private/target-checkpoint.json --output .private/preserved-carry.json --reason "恢复原因"
node scripts/recovery.mjs launch --origin https://dev.darkforest-pages-dev.pages.dev --secret-file .private/preview-rehearsal/secrets.json --input .private/preserved-carry.json
node scripts/recovery.mjs status --origin https://dev.darkforest-pages-dev.pages.dev --secret-file .private/preview-rehearsal/secrets.json
node scripts/recovery.mjs complete --origin https://dev.darkforest-pages-dev.pages.dev --secret-file .private/preview-rehearsal/secrets.json --input .private/preserved-carry.json
```

prepare先锁定业务写入并加密保全最新发行历史及完整证据，CLI保存成功后才执行launch。launch通过Cloudflare原生书签恢复并重启DO，连接可能随重启关闭；status中的标记应与检查点一致。complete检查实际恢复版本及码本，合并后发码为永久退役记录，保留已传播情报、通知发送状态与审计证据，并撤销全部旧会话。账号口令、启用状态和职责保留恢复前的最新值。重新登录后核对恢复结果，对缺少有效配置的玩家重新发放并确认穿戴，最后在系统状态页完成恢复核对。比赛仍保持暂停，由总裁判另行恢复。

启动前可使用cancel取消准备；材料尚未成功保存时，cancel可省略--input。已经恢复到检查点后应继续complete。恢复期间玩家行动及到期事件结算停止；已开始准备但尚未提交的写请求也重新检查恢复锁。目标检查点头部和密文共同接受完整性校验。schema版本或场次不一致的恢复文件不能用于本场。
