# 跨比赛账号与数据管理实现说明

日期：2026-11-05。状态：按用户确认的范围收尾。首次使用请看[办赛快速上手](办赛快速上手.md)。赛后文件改为主办方下载保管，见[赛后资料下载与保管补充](赛后资料下载与保管补充_2026-11-05.md)。长期账号与比赛身份分离、平台角色及跨场目录按用户授权的跨比赛方案执行。T0/T1、正式名单、两套时钟、手环码唯一性、QQ 人工职责和完赛判定沿用既有规则。

## 本地开始办赛

```powershell
npm run local:platform-setup
npm run dev
```

在另一个终端运行 `npm run admin:wizard`，选择本地环境，再选择“首次建立网站所有者”。向导核验站点与部署识别摘要，将领取材料保存到 `.private/platform-admin`。打开 `http://127.0.0.1:8788/claim` 领取，在网站用工作人员身份登录。`PLATFORM_BOOTSTRAP_SECRET` 仅用于首次安装和独立救援，不是网站长期口令；`BOOTSTRAP_SECRET` 保留给比赛恢复与旧场工具。云端配置 Worker 和 Pages 绑定，平台管理在非本地环境要求第二因素。

在“账号池”创建玩家和工作人员，交付领取链接。可通过 CSV 模板预览并导入；同名不合并，更新旧账号须明确填写账号编号。管理员创建正式比赛或试玩草稿，再进入本场管理页面邀请成员。工作人员接受后，由管理员或本场总裁判交接岗位；玩家接受后确认本场文明。三席与至少两名玩家准备齐后发布入口。正式名单仍由总裁判在场内选定，候选或已确认文明的玩家不会自动进入正式名单。

比赛地址为 `/m/<比赛编号>/player` 或 `/m/<比赛编号>/judge`；历史地址为 `/m/<比赛编号>/history`。工作人员直接打开历史地址时可带 `?audience=staff`。试玩使用同一规则引擎和独立比赛对象；可以复制活动说明、七色色值和八项比赛参数，新场人员、QQ群、时间、码本、成绩和任务从空白开始。玩家与工作人员使用独立 Cookie。场内尚未确认的写请求保留原比赛和请求编号；平台写入断线后可查询原编号并取消服务端未收到的请求。

## 技术与数据边界

Worker 新增 `DarkForestPlatform` SQLite Durable Object，比赛保留 `DarkForestMatch`；Wrangler 迁移为 `v2`，平台数据版本 1，比赛 Schema 8。注册后的比赛按明确路径经平台验证会话、目录和本场成员授权，最终比赛动作继续走原领域服务。新场用环境、场次及用途派生密钥。旧场接入保留原对象名、原 ID 和旧密文所用算法。共享 `MATCH_ID` 仅用于兼容旧单场入口；网站建场不依赖改配置。

跨对象新建、成员处理、席位交接、全局停用和清理由持久任务推进。任职单场原子切换；原任职失效后，旧预览失效，旧管理任务进入待核对。全局停用先拒绝发出新的场内授权，再登记各比赛的撤销结果；在本场收到撤销前，已经提交的请求可能已经完成。停用不自动淘汰文明。平台所有者、平台管理员与本场裁判分别授权；资料管理员的授权限定场次和期限。

赛后资料在请求时从本场记录生成，无需等待归档任务。在线历史使用比赛数据库，战报按版本读取，完整复盘按正式参赛事实或明确授权读取。平台所有者和获本场授权的资料管理员可下载；裁判操作记录和加密备份需要近期验证身份。网站记录下载操作，文件由主办方保管。

清理先核对完赛、保留期限、申诉保留和战报是否存在，登记七天待清理任务。执行时先写平台清理记录，阻止再下载完整复盘和备份，再裁剪比赛数据。正式战报及仍在保留期内的受限审计分开处理。清理过完整信息的比赛不能用旧检查点重新开放。原生存储仍可能在其恢复窗口内保有历史块，已下载的文件由主办方处理。

## 运维向导

`npm run admin:wizard` 使用中文菜单、隐藏凭据输入、文本确认和私有操作记录。向导提供在已配置站点上建立首次所有者、同部署旧场接入、检查点恢复、所有者失联救援、发布前核对、继续原恢复及脱敏诊断。

旧场接入先检查对象状态、保存加密检查点，再登记原对象。每个旧场账号建立独立的长期映射，旧会话撤销；参与者在领取页输入自己的旧口令兑换一次长期口令。旧日志中的个人身份无法确认时保留原席位记录。维护窗口和人员核对仍由主办方安排。

恢复时由总裁判先在网站暂停。向导读取检查点、锁住本场写入、生成加密保全材料并核对回读结果。服务器收到校验登记后才允许启动原生恢复。启动结果未知时查询原操作，不能盲目重发。合并后重新应用平台当前停用状态，保留比赛暂停和核对状态，由总裁判在网站完成核对后另行恢复。

## 验证与交付边界

- 跨比赛首轮本地验证覆盖平台首次安装和单次领取、正式场与试玩隔离、空草稿、重复建场、跨场拒绝、名单冻结、换总裁判、全局停用、申诉保留、到期清理、旧场原对象接入，以及模拟检查点回退后重新应用平台撤销。恢复回退使用本地 SQLite 测试路径，没有执行云端原生 PITR。
- 移除 R2 后增加赛后版本查看、按角色下载、停用归档包导入，以及单场清理标记回退后仍由平台拒绝完整复盘和旧检查点的定向检查。
- 内置浏览器已连接本地 Pages 和 Worker，操作工作人员登录、创建正式草稿、目录跳转，并检查桌面与 390 像素竖屏目录。页面和向导使用[前端文案规则](网站前端页面与功能规划.md#8-前端文案规则)。未执行两小时真实赛程、高成本负载测试、生产部署或 QQ 内置浏览器现场验收。
- 用户明确取消七项交付：旧裁判任务的专门接管界面、跨场个人统计、账号匿名化、终期清理、跨云迁移、密钥轮换、云端原生恢复验收。它们不再是待办或收尾条件。已有的裁判交接、旧任务待核对、逐场历史、到期复盘清理、同部署旧场接入和恢复向导保留。
- 赛后资料单次返回上限为 8 MiB；下载经过鉴权。本文记录本地交付，不将其视为生产部署、整个平台灾难恢复、运行池切换或云端回滚的验证记录。
