# 前端实现与开发预览

实施日期：2026-11-04。依据《网站前端设计系统》《网站前端页面与功能规划》。本次不修改两份受保护的核心文档，也不调整玩法规则。

## 启动与入口

使用仓库现有 Node.js 24、npm 11 环境，在项目根目录运行：

```powershell
npm ci
npm run dev:preview
```

已有依赖时可省略 `npm ci`。`dev:preview` 与 `dev:web` 启动同一台 Vite 服务，前者自动打开开发入口。默认端口5173，已被使用时直接访问正在运行的服务，不需重复启动。

| 入口     | 地址                                                                          | 数据来源                             |
| -------- | ----------------------------------------------------------------------------- | ------------------------------------ |
| 正式入口 | http://127.0.0.1:5173/                                                        | HttpSource，同源 `/api`，无模拟回退  |
| 开发预览 | http://127.0.0.1:5173/dev-preview/                                            | MockSource，本浏览器标签页的内存状态 |
| 裁判预览 | http://127.0.0.1:5173/dev-preview/judge?role=chief&scene=active               | 总裁判模拟会话                       |
| 终局核验 | http://127.0.0.1:5173/dev-preview/judge/endgame?role=chief&scene=verification | 98:00核验暂停与批量名单              |
| 观战预览 | http://127.0.0.1:5173/dev-preview/observer?role=observer&scene=observer       | 已永久淘汰满180秒的模拟会话          |
| 大屏预览 | http://127.0.0.1:5173/dev-preview/display?role=display&scene=active           | 裁判会话下的独立只读视图             |
| 赛后复盘 | http://127.0.0.1:5173/dev-preview/results?role=player&scene=ended             | 本场参赛者的完整复盘                 |

预览工具栏支持玩家、四维观察者、总裁判、通讯裁判、事件裁判、大屏6种角色。25组场景覆盖昵称、母星登记与审核、首航各步骤、正常出航、无资源、个人禁止目击、重生各步骤、最后一命、宇宙末日、转场、资格核验、最后狩猎、暂停、淘汰等待、观战、完赛和无冠军。角色与场景偏好只保存非秘密标识；实际模拟数据在刷新时重新生成。切换或重置场景会清除本次草稿和模拟操作。

“更多工具”可设置模拟目击结果、连接中断、会话失效、下次提交结果待确认；恢复连接请选择“正常”。“查看进入页”会结束当前模拟会话；预览登录接受非空示例口令。此行为仅存在于开发适配器。

`/dev-preview/` 和正式入口是 Vite 的两个HTML入口，共用 App、页面、组件、样式、权限展示和请求状态层，没有复制两套网站。`src/dev/mock-source.ts` 只由 `src/preview.tsx` 导入，正式入口不引用模拟模块。模拟入口不会读取真实比赛接口。

## 页面与交互

玩家保留“当前、行动、消息、我的”导航，覆盖功能规划列出的身份、登记、首航、目击、广播、光粒、重生、终局说明、淘汰、消息、情报、个人配置、记录、规则、联系、异常、账号页面。首航与重生只显示当前步骤；失去资格时撤下完整操作区。本人手环、历史、规则与已发生消息保留只读入口。

裁判使用职责筛选的侧导航，窄屏切为“工作台、待办、文明、更多”。页面覆盖母星审核、准备名册、通知、文明、终局批量核验、时间、事件、攻击复核、手环、效果、命令、系统状态、审计、结果与设置。审核和通知提交携带版本；复制与标记QQ已发送是独立动作。管理变更采用原因、预览、确认执行。指令输入作为数据交给适配器，不在浏览器执行脚本。

观战、文明详情、事件、结果、完整战报与文明复盘共用只读组件。大屏使用独立页面，不带裁判菜单；默认关闭自动轮播。全体淘汰时显示“本场没有存活冠军”。

七色色值集中在 `src/config.ts` 的初始配置；颜色身份与顺序在公共契约中固定。裁判“活动设置”可预览、保存新配置，所有色块通过当前 SiteConfig 读取。没有位图、渐变、地图、照片上传和定位功能。

## 切角轮廓与选色

`CutOutline` 根据 ResizeObserver 得到的实际宽高，绘制完整闭合SVG路径。左上、右下各有一条45度斜边，并与其他四条边连续描边。组件不依赖“普通矩形border加clip-path”；后者只裁掉矩形角，不会生成斜边。焦点使用第二条跟随切角的外轮廓。按钮、输入、任务框和手臂输入区复用此实现。

参考：[CSS-Tricks Notched Boxes](https://css-tricks.com/notched-boxes/)、[Sara Soueidan Clipping in CSS and SVG](https://www.sarasoueidan.com/blog/css-svg-clipping)。前者说明使用像素切角与calc保持45度的必要性；本次采用SVG实际轮廓处理连续描边，没有复制参考页面的渐变或装饰样式。

目击输入保留七个固定色盘位置。先选手臂再点色；颜色移入腕部后原格为空，点击腕部颜色可退回。可清空与整体交换，组内始终按固定颜色顺序呈现。同色全局唯一，编辑中允许未完成状态；单臂最多三条、总共最多四条，仅两条与一条、两条与两条、三条与一条可提交。

拖放使用 Pointer Events：鼠标移动超过6px开始，触摸长按约180ms提起，提起前的明显滑动保留滚动。支持色盘到手臂、跨臂、拖回色盘。唯一原色实体跟随指针；非法落点、Esc、指针取消、失焦、窗口变化都撤销拖动。点选转移用同一个实体的位移动画，减少动态效果时即时落位。

## 正式接口边界

现有 Functions 仍是透传中间件，Durable Object 仍是空业务类。本次没有实现正式服务或部署云端。真实登录、结算、全局状态、随机、发码、完整历史、命令执行与审计需要后端服务；前端模拟流程通过不构成这些能力通过验收。

`packages/contracts/src/index.ts` 提供前端DTO、颜色身份、状态枚举与允许动作。`src/data/http.ts` 集中同域请求、Cookie会话、CSRF头、超时、错误及只读投影。

| 待接能力                     | 前端约定                                                                                                   |
| ---------------------------- | ---------------------------------------------------------------------------------------------------------- |
| 会话恢复                     | `GET /api/auth/session` 返回 Session 或 null；登录使用原 `POST /api/auth/exchange`                         |
| 当前玩家                     | `GET /api/player/self` 返回 PlayerState，包括 actions、现役配置和各自时基的截止                            |
| 公开配置与时钟               | `/api/public/site-config` 返回 SiteConfig，`/api/public/match` 返回 MatchState                             |
| 本人历史                     | `/api/player/messages`、`/api/player/intel` 返回本人授权的事件与情报                                       |
| 裁判工作空间                 | `/api/judge/overview` 返回按职责裁剪的 judge、civilizations、events，以及完赛时的 results                  |
| 管理预览                     | `POST /api/judge/manage/preview` 返回 ManagementPreview，实际写请求携带 preview_token 与 expected_revision |
| 未确认操作                   | `GET /api/operations/:requestId` 查询原操作结果，不把没有记录直接判为操作失败                              |
| 大屏与复盘                   | `/api/judge/display`、`/api/results/overview`、`/api/results/events` 返回各自范围的只读数据                |
| 通知、审核、准备、时间等写入 | 沿用规划与技术方案中的业务路径；新增设置、效果与预览路径需后端实现                                         |

这些是本次前端对接契约，新增或扩充部分需后端落实与联调；不能直接把旧技术文档示例JSON当作已经兼容的返回值。现阶段裁判工作空间通过overview聚合读取，正式接入大量历史时应按页面拆分、分页；不要无条件返回整库或未来计划。

客户端普通存储只保存待确认请求的标识、动作路径、账号和场次，以及阅读偏好；不保存口令、整套颜色草稿、母星秘密或登录凭证。正式与预览请求记录分开命名。提交结果不明时锁定新提交并查询原请求；资格撤销立即清除相应秘密与草稿。断线保留当前已授权内容和同步时间，停止写入；回到页面或恢复网络时刷新。

MockSource只用于浏览页面与走常见流程。固定目击结果、示例排名、简化管理预览及指令返回不是完整比赛引擎；复杂纠错传播、任意指令、全局并发、完整码本永久唯一性与跨刷新模拟恢复不在其保证范围。刷新后模拟请求记录重建；若正查看待确认请求，请重置场景重新演示。

## 本次验证范围

采用前端构建、前端TypeScript、改动文件ESLint，以及 `tests/unit/frontend.test.ts` 的针对性测试。未执行全量单元、Workers集成或端到端测试。

浏览器检查覆盖手机和桌面页面、先选臂再点色、合法组合确认出现、颜色移出后原位为空，以及跨臂鼠标拖动。补充检查裁判工作台、角色切换、直接链接和状态披露。未做iPhone Safari、Android和QQ内置浏览器真机验收，触摸长按阈值仍需实际使用调校。

正式后端不可用，未宣称真实比赛联调、服务端授权或规则验收完成。
