# 代码规范

本项目保留 Prettier、ESLint 和现有 TypeScript 严格配置，以 [Google TypeScript Style Guide](https://google.github.io/styleguide/tsguide.html) 为规范来源。采用日期为 2026-11-06；该页面当前标题为 TS/JS Style Guide，来源与逐节检查方式见 [Google 指南规则映射](Google_TypeScript_规则映射.md)。工具通过不代表所有命名、职责和文档要求均已满足。

本次全库迁移的人工评审结论、保留的环境适配、全新检出验证及证据边界见 [规范验收](代码规范验收_2026-11-07.md)。后续改动继续执行本文要求。

## 适用范围与优先级

适用于手写 TS、TSX、JS、MJS 及其测试、工具脚本。生成文件、依赖、构建结果和私有运维材料不参与风格迁移。数据库列名、JSON 键、HTTP 路径、命令文本、Cloudflare 绑定名和包名属于外部契约，不能随着内部命名迁移改变。手写声明文件仍按文件命名规范检查。

游戏规则以核心原文及用户授权的补充修正为依据。重构保持权限条件、时间基准、结算顺序、幂等、序列化格式与信息可见性。修改具体行为前必须沿 [文档导航](ai/文档导航.md) 核对相应原文。两份核心文档继续排除在自动格式化外；需要修正文案时另增补充文档。

## 格式与语言使用

JS/TS 使用两空格、LF、分号、单引号、尾逗号、不在对象花括号内留空格；单参数箭头省略括号。Prettier 的 `printWidth: 80` 是排版目标，不设置硬性 `max-len: 80`。Markdown、CSS、JSON 等继续使用原有 100 宽度配置。

使用 `const` / `let`，每条声明一个变量；统一给控制流加大括号。这比指南允许部分单行省略的写法严格，是本项目的额外约定。严格相等检查允许 `== null` / `!= null`。禁止 `eval`、字符串构造函数、包装对象、`const enum` 和手写 namespace；ES modules 采用具名导出。框架固定默认导出入口只豁免默认导出限制，仍执行其他语言规则。

对象类型优先用 `interface`；联合、交叉、映射和元组保留 `type`。简单数组使用 `T[]`，复杂元素使用 `Array<T>`。类型导入使用 `import type` 或内联 `type`，避免在函数签名内散落 `import('...').Type`。

类型断言使用 `as`，对象字面量通过声明处的类型标注接受字段检查，不通过 `as Contract` 绕过。`as const` 的字面量收窄仍允许。自定义 CSS 属性用明确的样式接口表达；测试夹具优先构造完整契约。

类型别名不在顶层联合里隐藏 `null` / `undefined`，在使用位置明确写出缺失状态。类使用 TypeScript 的 `private` / `protected`，不使用 `#private`。模块级命名函数优先函数声明；为显式函数接口类型保留的箭头函数是例外。类方法和构造器与周围代码之间保留空行，重载签名保持为一组。永不重新赋值的成员使用 `readonly`，不把引用只读误解为深度不可变。

避免新增仅由返回类型决定的泛型 API。既有 HTTP、SQL、DOM 与数据 Hook 的这类调用显式填写类型参数；`explicit-return-generics` 使用实际选中的重载签名和类型参数符号检查，保留可从参数推断的普通泛型调用，不自动猜测应填写什么类型。类型参数只说明调用方采用的契约，不等于执行了运行时响应验证。新的边界优先让输入、解码器或已知契约决定返回值。

类型、类和接口使用 UpperCamelCase；普通变量、参数和函数使用 lowerCamelCase。真正共享的常量可以使用 CONSTANT_CASE；不能把每个 `const` 都改成大写。React 组件允许 UpperCamelCase。当前自动规则允许变量使用组件名及常量名，是否符合用途需要人工审查。短局部变量只在上下文足够清楚时使用；导出的 API 应使用描述性命名。

手写文件使用 `snake_case`，测试保留 `.test.ts` / `.test.tsx` / `.test.mjs` 后缀，声明保留 `.d.mts` 等后缀。框架固定入口 `eslint.config.mjs`、`vitest.config.ts`、`vitest.workers.config.ts`、`apps/web/vite.config.ts` 与 Pages `_middleware.ts` 是明确例外。npm 命令名和 workspace 目录名保持现有调用契约。具体名单由 `scripts/check_source_names.mjs` 执行。

## 自动门禁

| 范围           | 工具与要求                                                                                                      |
| -------------- | --------------------------------------------------------------------------------------------------------------- |
| 全库格式       | Prettier，配置见 `.prettierrc.json` 和 `.prettierignore`                                                        |
| 全库语言和风格 | ESLint recommended、typescript-eslint recommended、大括号、单声明、相等、类型定义、数组、命名和具名导出         |
| TS 错误屏蔽    | 产品代码禁止 `@ts-ignore`、`@ts-nocheck`、`@ts-expect-error`；仅测试允许附至少 10 字符说明的 `@ts-expect-error` |
| 无效 lint 屏蔽 | `reportUnusedDisableDirectives: error`，不留下过期豁免                                                          |
| 前端和公共契约 | 保留禁止导入 Worker、Functions 和 Cloudflare 私有依赖的边界规则                                                 |
| React 源码     | `rules-of-hooks`、`exhaustive-deps` 均为 error                                                                  |
| 全库类型安全   | 所有 TS、TSX、MTS、CTS 使用 `recommendedTypeChecked` error；没有目录豁免或迁移基线                              |
| 所有 TS 项目   | 保留 strict、noUncheckedIndexedAccess、exactOptionalPropertyTypes 等现有检查                                    |
| 模块与类型表达 | 禁止 `const enum`、import-equals、export-assignment、动态 import 类型、可空顶层类型别名与 `#private`            |
| 函数与文档     | 产品和脚本导出声明有 JSDoc；命名函数声明、类方法间距由本地规则执行，语义质量仍须评审                            |
| 文件区段       | 所有导入置于实现之前，两区段之间一空行；本地 module-layout 只自动修复空行，导入次序与副作用由人工核对           |
| switch 分支    | 必须有末尾 default；TypeScript 禁止非空分支贯穿                                                                 |

Prettier 冲突配置在规则合成末尾应用；随后显式恢复与 Prettier 兼容的 `curly: all`。工具回归测试验证实际生效的规则，避免配置覆盖造成漏检。

TS 类型环境按现有前端、Pages Functions、Worker、contracts、工具、前端测试及 Workers 测试的 tsconfig 分别解析。Node 运维 MJS 使用 JS 规则。Wrangler 类型必须先生成；从全新目录也能运行检查，不能依赖已有 `.wrangler/types`。

`npm run check` 执行：格式检查 → Wrangler 类型生成 → 文件名与全库类型感知 lint → 纯 TypeScript 检查 → 前端和 Worker dry-run 构建。`npm run typecheck` 仍保留独立使用时的类型生成；`typecheck:ts` 供已生成类型的流水线使用。

## 全库类型安全

`npm run lint:audit` 使用正式 ESLint 配置，对全部手写 TypeScript 输出类型感知报告，写入 `.tmp/style-migration/lint-audit.json`。任何诊断都会返回非零。它不会修改源码，也不会把报告改成 warning。

迁移期间的 499 条报告已清零，`typedFiles` 范围名单、审计专用配置、`lint:ratchet` 与迁移基线已删除。正常 `npm run lint` 直接强制全部规则。后续不得重新引入基线、目录级关闭或无依据的断言绕过检查。

公共 `parseJson` 返回 `unknown`；权限数组、数值设置和外部标量使用相应验证器收窄。对象不能通过 `String(value)` 变成标识符或日志中的 `[object Object]`。`scalarText` 保留合法标量的既有转换及六位文本中的前导零，并拒绝对象和数组。

DOM 异步事件使用 `handleAsync` 把失败交给实际 UI 反馈；不能只丢弃 Promise。测试使用 `promiseStub` 明确模拟 Promise 接口，保持同步执行准备工作、异常转拒绝及参数传递，不增加无关 await。

异常只抛出 `Error` 及其子类；`Promise.reject` 和 `AbortController` 的显式中止原因同样遵守该契约。Cloudflare `DurableObjectState.abort` 的对象重启接口要求字符串原因，按其平台签名调用并就地说明。读取未知捕获值的消息时，使用共享 `requireError` 保留原异常并验证契约，不能无依据地把非 `Error` 值转换为普通业务失败。只有已确认某个调用API违反契约时才处理它的非 `Error` 抛出值，并就地写明具体来源。按业务错误子类或 `AbortError` 名称分流仍须保留；安全边界的固定脱敏响应不应改成泄露内部消息。

## 人工评审

- 先通过 CodeGraph 核对调用关系，再限定模块重构。格式化、文件迁移和语义修复应分别检查 diff；涉及业务行为时读取规则原文。
- 导出符号的 JSDoc 解释用途、约束、副作用和失败条件；工具固定入口可使用指南允许的例外。顶部导出声明的文档存在性已有门禁，不能用重复函数名的注释代替说明，也不能以覆盖率证明信息量。
- `unknown` 在外部输入边界收窄。JSON 解码、数据库行和 RPC 响应的断言必须能指出验证器、写入方或 Schema 依据；不能以 `as unknown as ...`、`any` 或无依据断言代替修复。
- Google 允许有依据的 `as`、非空断言和类型推断；不全库禁止 `!`，也不强制所有函数手写返回类型。公共 API 是否需要显式返回类型按可读性决定。
- 异步错误必须有实际归宿。不能随手加 `void`、空 catch 或无关 await 使 lint 变绿；测试中的异步接口与 Promise stub 也需要逐项判断。
- 命名应面向新读者；组件、职责、模块边界和公开接口的稳定性需要人工判断。长度和复杂度阈值尚未建立，不宣称它们是 Google 的要求。
- SQL、权限、调度与恢复模块必须用现有集成测试验证。纯格式通过、类型通过和构建通过分别说明，不替代浏览器视觉检查、真实现场或线上验收。

## CI 与提交

现有 CI 保持 `npm ci` → `npm run check` → `npm test`，其中测试包含规范工具回归、单元测试与 Workers 集成测试。`.github/workflows/ci.yml` 的检查会随 package scripts 自动加强。远端 required check 仍需在 GitHub 分支保护或 ruleset 中配置，仓库文件本身不能保证禁止合并。

迁移 diff 按规范配置、机械格式、命名与类型兼容、模块提取分别审查。用户已授权 add、commit 和回滚；只在 `refact` 或从它新建的衍生分支工作，不修改其他既有分支。只有实际产生纯格式提交后，才将其真实 SHA 加入 `.git-blame-ignore-revs`，不写占位值。
