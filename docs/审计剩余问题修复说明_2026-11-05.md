# 审计剩余问题修复说明

本轮在完整指令系统落地后，复核并关闭[审核报告](审核报告.md)中上轮暂缓的 F09 命令部分、F10 事件命令部分及 F11。原有 F01—F08 和普通管理修复见[首轮修复说明](审计修复说明_2026-11-05.md)。本轮依据[完整指令规划](裁判员指令系统完整规划.md)及实际代码，不把规划或先前测试记录当作本轮完成证明。两份受保护的核心文档没有修改。

## F09：命令记录与业务审计

复核时已有独立命令日志和加密原文，但主要记录变化摘要；计划查询、请求查询和取消未完整留痕，定时执行与作业步骤缺少实际前后状态和结果关联。本轮补齐：

- 确认执行和直接保存记录原因、来源、实际对象、预览、实际业务前后状态、结果及关联审计ID。业务快照覆盖资源、飞船、母星、手环退役、处罚、淘汰、计划、通知、账号状态、标签和管理对象状态；不包含登录口令、会话令牌摘要或手环加密索引。
- 独立记录查询、预览、取消、拒绝、成功、无操作、已消费计划的结果重放。查询保存条件、投影、水位和数量，不复制整份查询秘密正文；检索词保留在加密原文。
- 定时任务和逐步作业记录父任务、计划事件、执行步骤、实际前后状态、结果、失败或取消原因。定时子执行不会误用当时另一个HTTP请求的密文。
- 原文密文改为请求内传递，避免同一Engine并发处理命令时串用共享字段。原始操作及`confirm`各自保存对应请求原文，计划ID连接原始预览与实际执行。
- `/command history`及`GET /api/judge/command/history`可按对象、操作者、命令路径、状态、时间和原因检索；筛选先于分页。普通返回不包含原文密文，需具备审计权限。

示例：

```text
/command history --target C07 --status executed --limit 30
/command history --kind "penalty wrong-set" --search "复核处罚"
/audit inspect AUDIT-ID
```

`--kind`在命令历史中表示实际命令路径；`auditId`是日志返回的真实业务审计ID。旧记录未保存的前后状态不能补造，旧密文若曾发生错绑也不会在本轮自动重写；完整新增字段用于本轮之后的新操作。

## F10：事件命令

现有系统已经实现`/event list`、`/event inspect`、`/event trigger singer`、`/event trigger tech-burst`、取消与重试。本轮补充验证并修复重试结果：

- `/event list`查询实际计划表，`/event-log list`单独查询已发生事实；旧示例`/events list`按完整规划迁移为单数`/event list`，不恢复旧的混用语义。
- `--status failed`筛选仍为pending且有持久错误信息的计划，保留原始状态、失败次数和错误说明；不要求改数据库状态枚举。
- 已结算事件的retry为无操作，返回原计划及已发生结算事实，不重复抽奖、改变原时刻或生成通知；取消和未到期事件明确拒绝。
- 手动歌者确认产生独立管理来源；同请求重试不重复清理，不改变已存在的自然计划。自然技术爆炸、额外定向奖励等仍沿已完成的完整指令设计执行。

```text
/event list --status failed
/event inspect EVT-ID
/event retry EVT-ID
/event trigger singer 001234
```

以上写操作继续经过真实预览、最终权限检查及统一事务。故障处理例外保留，不扩大为绕过积压继续普通战局写入。

## F11：选择器与独立历史

现有目标服务已支持`@alive`、`@dead`、`@random[alive]`以及状态、母星、标签和数值范围筛选。本轮新增复核保证正式名单外账号不进入这些集合，合法返航者仍属于存活文明；修复`@random[alive,sort=id]`被显式排序误变成固定选人的情况，`@random`始终保持均匀抽一人的含义。预览只显示候选，实际抽取在确认时完成，同请求重放不重抽。

原`history kind command`仍误查普通业务审计，默认历史也只读事件表。本轮改为独立文明历史汇总：

- 默认`all`合并职责允许的事件、航次、淘汰、攻击、通知及处理履历、命令和业务审计。
- 分类`attack`、`flight`、`homeworld`、`resource`、`elimination`、`notice`、`command`分别读取对应事实；`command`读取真正的`judge_command_log`，包含批量命令中实际涉及该文明的记录。
- 补充`penalty`和`correction`两种分类，分别查询原攻击处罚、管理处罚/赦免，以及攻击纠错和其他业务修正。共享帮助、自动补全及规划EBNF同步这两个类别。
- 跨表分页采用每个来源的首屏行号上限及“时间、来源、来源内位置”游标；筛选先于分页，每页重新检查权限。游标绑定文明与条件，不能换一个对象继续使用。它固定新增记录水位，不伪装成旧状态的全库快照。
- 当前状态仍由`/inspect`返回；历史返回含类别、来源和原始业务记录的列表。无审计职责的裁判不会从默认历史获得攻击抽签、完整审计或命令日志，显式请求受限类别会被拒绝；玩家无指令入口。

```text
/selector inspect @random[alive]
/history C07 kind attack --limit 30
/history C07 kind penalty
/history C07 kind correction
/history C07 kind command --status executed
/history C07 kind notice --search "重生"
```

本轮保持Schema 7，没有新增数据库迁移。既有命令日志、审计、通知履历及恢复保全继续使用原表，不建立第二套权威记录。界面帮助由同一共享命令目录生成，新增分类与状态筛选也进入补全。

## 本地验证及边界

新增真实workerd回归覆盖：命令前后状态及审计关联、加密原文、同Engine并发请求原文绑定、计划/请求查询、取消及拒绝、原请求与已消费计划重放、定时子执行、计划与事件事实分离、失败筛选、取消/未到期拒绝、已结算重试、手动歌者幂等、选择器范围和随机抽取，以及混合历史权限、120条旧记录检索和跨页水位。新增共享契约测试检查历史类别及状态补全。

验证仅使用本地自动化、临时SQLite和可控时钟，不进行完整两小时排练、真实校园、校园网络、QQ送达、移动设备或实物验收；未进行云端部署。本轮未重新做浏览器视觉验收。

本轮最终结果：

- `npm test`通过：5个单元/React测试文件共45项，3个真实workerd测试文件共76项，合计121项。相对指令系统首次交付的110项，本轮新增1项共享契约回归及10项真实workerd回归。
- `npm run check`通过：全仓Prettier、ESLint、各工作区与测试/工具TypeScript检查、前端生产构建及Worker构建dry-run。dry-run没有部署资源。
- `git diff --check`通过，两份受保护核心文档无改动。
- 故障注入用例仍会打印损坏事件引发的预期Alarm失败及本地Alarm调度诊断；测试结果全部通过，不将这些注入日志误写成真实场次故障。

主要实现位于`apps/match-worker/src/services/commands.ts`、`civilization_history.ts`、`command_targets.ts`及`engine.ts`；回归位于`tests/workers/commands.test.ts`和`tests/unit/commands.test.ts`。原有历史缺失不会被伪造补齐，本轮的新记录具有完整关联信息。
